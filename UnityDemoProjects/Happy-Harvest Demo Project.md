# Happy Harvest 기반 게임 제작 강의자료

Nov 13, 2026 · @YongHwan Lee

공통 프로세스 강의노트 템플릿의 《 》를 Unity 공식 2D URP 샘플 Happy Harvest 기준으로 채운 게임별 강의자료다. 공통 본문(학습 목표·방법론·양식)은 템플릿을 그대로 쓰고, 여기에는 Happy Harvest에서만 달라지는 내용만 적는다.

## 0. 게임 개요와 강의 설계

Happy Harvest는 Unity가 2023년 7월 공개한 2D 탑다운 농장 시뮬레이션 샘플로, "부지런한 농부의 하루"를 배경으로 2D 라이트·그림자·스켈레탈 애니메이션·타일맵·VFX를 한 프로젝트에서 보여준다. 게임 로직은 일부러 단순하게 썼고(개발자가 "아티스트도 읽을 수 있게 최적화보다 단순함을 택했다"고 밝힘), 팀·퀀스트·상점·진행 시스템이 없어 "추가 기능 도출" 수업에 잘 맞는다.

## 1. 0주차 — 강사 사전 준비

수업 전에 강사가 직접 열어 본 버전을 한 개로 고정하고, 학생 분석을 채점할 정답 분석서를 먼저 만든다.

- [ ] Unity Hub에 Unity 6.3 LTS(6000.3.x) 설치, Unity 6 호환이 표기된 Happy Harvest 1.6x로 확인
- [ ] 새 2D(URP) 프로젝트 생성 → Package Manager > My Assets에서 Happy Harvest 임포트 → 프로젝트 설정 변경 팝업 모두 수락 → 콘솔 경고 목록 캐프처(학생에게 "정상 경고"로 배포)
- [ ] 실내·실외 씬 모두 플레이해 다음을 확인: 경작→물→씨앗→성장→수확, 낮/밤 전환, 실내 출입 후 작물 수확 가능 여부(포럼에 보고된 버그 — 현재 버전에서 수정되었는지 기록)
- [ ] `Assets/HappyHarvest/Scripts` 폴더의 스크립트 목록을 뽑아 정답 기능분해표(양식 A)와 클래스 관계도 작성 — 아래 2번 섹션의 초안을 실제 파일명으로 확정
- [ ] 핵심 루프 1회(클릭 → PlayerController → Terrain Manager → 타일 변경)를 브레이크포인트로 따라가며 시범용 스크린샷 확보
- [ ] 강사 시범 구현(4번 섹션: 새 작물 1종 추가)을 미리 끝까지 해 보고 소요 시간·함정 기록
- [ ] WebGL 빌드 1회: 용량·로딩 시간 기록(5번 섹션 목표치의 근거), 터치 미지원 확인
- [ ] 템플릿 Git 저장소: 임포트 직후 상태를 초기 커밋, `.gitignore`(Unity), Git LFS(png·psb·wav·vfx), Force Text 직렬화 확인 → 팀별 fork. 샘플은 Asset Store 전용 배포라 GitHub 공개 저장소는 비공개(private)로 운영
- [ ] 학생 계정 과제 공지: Unity ID, GitHub, itch.io

**실습실 요구사항**: VFX Graph·2D 라이트 때문에 내장 GPU에서는 에디터 FPS가 낮을 수 있다(포럼 보고). 게임 뷰 해상도를 낮추거나 Scene 뷰 이펙트를 꺼두는 요령을 1주차에 안내.

## 2. 1단계 분석 (1주) — 기능분해 → 소스분석 → 현황 파악

Happy Harvest는 "타일맵이 곷 게임 상태"라는 점이 분석의 열쇠다. 땅의 상태(갈았는가·젖었는가·무엇이 심겨 있는가)가 별도 데이터 구조가 아니라 Grid 아래 타일맵 레이어에 저장되고, Terrain Manager가 Tilemap API로 이를 읽고 쓴다. 학생이 이 구조를 이해하면 나머지는 쉭다.

**기능분해표 초안 (강사 정답본 골격 — 학생에게는 대분류까지만 개방)**

| 대분류 | 기능 | 세부 동작 | 담당 씬/오브젝트 | 담당 스크립트·데이터 (0주차에 파일명 확정) | 현황 |
| --- | --- | --- | --- | --- | --- |
| 코어 루프 | 경작 | 호미 사용 → Tillable 타일을 Tilled 타일로 교체 | 실외 씬 Grid > GroundBase, TilledTilemap | PlayerController → Terrain Manager, GroundData | ● |
| 코어 루프 | 물주기 | WateredTileLayer에 젖은 타일 페인트, 일정 시간 후 마름 | WateredTileLayer | Terrain Manager, GroundData(젖음 지속 시간) | ● |
| 코어 루프 | 씨앗 심기 | Tilled 타일에만 식재, Crop 타일맵에 배치 | Crop 타일맵 | Terrain Manager, CropData, CropInitializer | ● |
| 코어 루프 | 작물 성장·고사 | CropData의 성장 속도·생존 시간에 따라 단계 타일 교체 | Crop 타일맵 | Terrain Manager(Update), GameManager(작물 데이터 보관) | ● (Update 비효율 — 개발자 인정) |
| 코어 루프 | 수확 | 클릭 시 HarvestAt → 인벤토리 추가, VFX 재생 | Crop 타일맵 | Terrain Manager, 인벤토리 | ◐ (실내 출입 후 VFX 참조 유실 버그 보고 — 현 버전 확인) |
| 코어 루프 | 인벤토리 | 단일 슬롯 스택, 씨앗·수확물 보관 | HUD | 인벤토리 스크립트 | ◐ (1슬롯 — 확장 포인트) |
| 콘텐츠 | 작물 3종 | 밀·당근·옥수수, 성장 단계별 타일 | Crop 타일맵 | CropData 에셋(데이터) | ● |
| 콘텐츠 | 사과 나무·동물 | 사과 따기, 돼지·소 먹이주기 | 실외 씬 오브젝트 | 상호작용 오브젝트 스크립트 | ◐ (보상·목적 없음) |
| 시스템 | 낮/밤 | 시간 경과에 따라 글로벌 라이트·색 보간 | 실외 씬 Lights | DayNight 보간 스크립트 | ● (게임플레이와 미연결) |
| 시스템 | 씬 전환 | 집 출입, 2D 페이드 | 실내/실외 씬 | 씬 전환·페이드 시스템 | ● |
| 시스템 | 저장 | 작물 데이터 영속화 | — | GameManager(영속), 세이브 시스템 | ◐ (범위 확인 필요) |
| 시스템 | 입력 | WASD 이동, 마우스 클릭 상호작용 | — | PlayerController, Input System | ◐ (터치 미지원) |
| UI·연출 | HUD·캐릭터 애니메이션·VFX | 인벤토리 표시, 스켈레탈 애니메이션·IK, 비·불·나뭇잎 | — | Animator, VFX Graph, Particle | ● (분석 범위 밖: 셰이더·VFX 내부) |
| 메타·진행 | 목표·재화·상점·종료 조건 | — | — | — | ○ 없음 |

**소스분석 경로 (강사 시범 + 학생 반복)**

1. 진입점: 초기 씬과 GameManager가 어떻게 영속(DontDestroyOnLoad)되는지, 실외 씬 로드 시 CropInitializer가 작물을 다시 심는 순서
2. 클릭 1회의 여정: 마우스 클릭 → `Camera.main.ScreenToWorldPoint` → 셀 좌표(Vector3Int) 변환 → 들고 있는 도구·아이템 분기 → Terrain Manager 함수 호출 → 타일 교체. 이 경로 한 줄이 호출 흐름 다이어그램의 전부다.
3. 데이터와 로직 분리: GroundData / CropData에 무엇이 들어 있는지(젖음 지속, 성장 속도, 고사 시간)를 표로 정리 — 2단계에서 "데이터만 추가해도 되는 기능"을 고를 근거
4. 타일맵 레이어 역할표: GroundBase / TilledTilemap / WateredTileLayer / Crop / ObjectsInTiles / Water / Warehouse·House — 각각 "누가 쓰고 누가 읽는가"
5. 재사용 가능 시스템 표시: 세이브·씬 전환·페이드·낮/밤은 개발자가 "다른 프로젝트에 그대로 가져갈 수 있다"고 밝힌 부분 — 건드리지 말고 쓰는 쪽으로 분류

**일부러 비어 있는 곳 (현황 보고서의 확장 포인트 후보)**: 수확물의 용도 없음(재화·판매 부재) · 낮/밤이 연출에만 쓰임(작물 성장·피로·상점 영업과 미연결) · 인벤토리 1슬롯 · 동물 먹이주기에 보상 없음 · 게임 목표·종료 없음 · 터치 입력 없음

**분석 제외 영역**: Shader Graph(물·식물 흔들림), VFX Graph 내부, 2D IK·얼굴 리깅, 노몀·마스크 맵 제작 — "보고 설명할 수는 있지만 수정하지 않는다"로 선언

**점검 질문 (Happy Harvest 전용)**: 경작한 땅의 상태는 어느 타일맵에 있는가? 집에 들어갔다 나오면 작물은 어떻게 복원되는가? 작물의 성장 속도를 바꾸려면 코드를 고쳐야 하는가, 에셋을 고쳐야 하는가?

## 3. 2단계 설계 (1주) — 추가 기능 도출 → 구현 방향과 가이드

Happy Harvest는 "농장 하루"는 있지만 "게임"이 없다 — 목표도, 재화도, 끝도 없다. 그래서 기능 후보는 대부분 "수확물에 의미를 부여하는 것"과 "콘텐츠를 늘리는 것" 두 갈래로 모인다. 장르 관습 레퍼런스: 스타듀 밸리, 하랄보이스타일, 쿠키런 킹덤의 테라리어 농장.

**강사 제시 기능 후보 10개와 2×2 분류**

| # | 기능 (사용자 스토리) | 가치 | 난이도 | 분류 | 확장 방식 |
| --- | --- | --- | --- | --- | --- |
| 1 | 새 작물 1종(예: 호박) — 플레이어는 새 씨앗을 심고 자라는 것을 보고 수확할 수 있다 | 중 | 하 | 시범 구현 | CropData 에셋 + 성장 단계 타일만 추가 (코드 변경 0) |
| 2 | 판매 상자·재화 — 수확물을 창고 상자에 넣으면 금화가 늘고 HUD에 표시된다 | 상 | 하 | 필수 | 새 상호작용 오브젝트 + GameManager에 금화 필드 + HUD 텍스트 |
| 3 | 씨앗 상점 — 금화로 씨앗을 사서 인벤토리에 넣는다 (2번과 한 쌍) | 상 | 중 | 필수 | 상점 오브젝트 + 가격 데이터(SO) + 간단한 UI 패널 |

| 5 | 하루 리듬 — 밤이 되면 잠들어 다음 날로 넘어가고 작물이 하루치 성장한다 (낮/밤 시스템을 게임플레이와 연결) | 상 | 중 | 도전 | DayNight 스크립트에 이벤트 추가 + 침대 상호작용 + Terrain Manager 성장 틱 호출 |
| 6 | 게임 목표·종료 — 7일 안에 금화 500 모으면 결과 화면 | 상 | 하 | 필수(5번 전제) | GameManager 상태 확인 + 결과 UI |

| 8 | 도구 업그레이드 — 물뿌리가 3×1 범위를 적신다 | 중 | 중 | 보류 | PlayerController 도구 분기 수정(위험 중) |
| 9 | 터치 입력 — 모바일 브라우저에서 탭으로 상호작용 | 중 | 중 | 배포 선택 과제 | Input System 액션 추가, `Mouse.current` 의존 제거 |
| 10 | 저장/불러오기 확장 — 금화·인벤토리·날짜도 저장 | 중 | 중 | 도전 | 기존 세이브 시스템에 필드 추가 |

권장 조합: **필수 = 판매·재화(2) + 씨앗 상점(3) 또는 다슬롯 인벤토리(4)**, **도전 = 하루 리듬(5)+목표(6)** — 이 세트가 모이면 "씨앗 사기 → 심기 → 재우기 → 판매 → 목표 달성"의 완결된 게임 루프가 생긴다. 팀마다 새 작물 추가(1)는 시범 따라하기로 모두 수행.

**이 게임이 유도하는 확장 방식**: ① 작물·지면 속성은 CropData/GroundData 데이터 추가로 ② 새 상호작용은 기존 상호작용 오브젝트 패턴을 따르는 새 컴포넌트로 ③ 전역 상태(금화·날짜)는 이미 영속 오브젝트인 GameManager에 필드로 ④ PlayerController·Terrain Manager 내부 수정은 최후에.

**금지 범위**: 셰이더·VFX Graph 신규 제작, 캐릭터 리깅 변경, 타일맵 레이어 구조 변경(새 레이어 추가는 가능).

**명세서 예시 — #2 판매 상자·재화** (양식 C)

| 항목 | 내용 |
| --- | --- |
| 사용자 스토리 | 플레이어는 수확물을 들고 창고 앞 판매 상자를 클릭하면, 수확물이 사라지고 작물별 가격만큼 금화가 늘어 HUD에 표시된다 |
| 도출 근거 | 현황 보고서 "수확물의 용도 없음" / 플레이 테스트 "수확하고 나면 할 게 없어서 그만둠" / 농장 장르 관습(출하 상자) |
| 우선순위 | 가치 상 × 난이도 하 → 필수 |
| 수정 대상 | GameManager(금화 필드·변경 이벤트 추가), HUD 프리팹(금화 텍스트 추가), 실외 씬(상자 배치) |
| 신규 추가 | `SellBox` 컴포넌트(기존 상호작용 오브젝트 패턴 따름), 작물별 판매 가격(CropData에 `sellPrice` 필드 추가 또는 별도 PriceTable SO), 상자 스프라이트 1장 |
| 확장 방식 | 데이터 추가 + 새 컴포넌트. GameManager에는 필드와 이벤트만 추가(기존 메서드 변경 없음) |
| 설계 | SellBox.OnInteract → 인벤토리에서 현재 아이템이 수확물이면 수량×가격을 GameManager.AddGold에 전달 → GameManager가 OnGoldChanged 이벤트 발생 → HUD가 구독해 텍스트 갱신 |
| 수용 기준 | ① 밀 3개를 들고 상자 클릭 → 인벤토리 0, 금화 +3×밀 가격 ② 빈손·도구를 들고 클릭 → 아무 일도 없고 에러 없음 ③ 금화 변경 시 HUD가 같은 프레임에 갱신 ④ 집에 들어갔다 나와도 금화 유지 |
| 리스크 | 인벤토리가 1슬롯이라 "수확물을 들고 있다"의 판정이 단순 — #4와 함께 할 때 인터페이스 먼저 합의 |
| 구현 가이드 | (1) CropData에 가격 필드 추가하고 3종 작물 에셋에 값 입력 → (2) GameManager에 Gold·AddGold·OnGoldChanged 추가, 콘솔로 확인 → (3) SellBox 스크립트 작성, 상자 프리팹에 부착, 씬 배치 → (4) HUD에 텍스트 추가하고 이벤트 구독 → (5) 수용 기준 4개 테스트. 예상 4\~6시간 |

## 4. 3단계 구현·테스트 (2주) — 기능 구현 → 테스트

강사 시범은 "코드를 한 줄도 안 고치고 기능을 추가하는" 새 작물 추가로 시작해, 데이터 주도 확장이 무엇인지 몸으로 느끼게 한다. 그 다음 팀이 판매 상자로 "새 컴포넌트 + 기존 클래스 최소 수정"으로 넘어간다.

**강사 시범 구현 — 새 작물 「호박」 추가 (약 50분, 라이브)**

1. `feature/crop-pumpkin` 브랜치 생성 → 기존 당근 CropData 에셋을 복제해 이름·성장 속도·고사 시간 변경
2. 성장 단계 스프라이트(씨앗·새싹·성장·수확 가능 4장)를 기존 작물 스프라이트 규격(픽셀 크기·피붇·노멀 맵 유무)에 맞춰 제작 — 아트는 강사가 미리 준비해 배포
3. 씨앗 아이템 데이터를 추가하고 인벤토리 초기값 또는 실내 씨앗 상자에 연결(프로젝트에서 씨앗을 얻는 경로를 0주차에 확인해 기록)
4. 플레이 확인 → 커밋 → PR → 학생이 리뷰 체크리스트로 리뷰 → 머지
5. 질문으로 마무리: "코드를 고치지 않았는데 왜 가능했나?" → 1단계에서 찾은 데이터/로직 분리로 연결

**따라야 할 기존 규약 (0주차 정답 분석서에서 확정 후 배포)**

- 전역 상태는 영속 GameManager 한 곳에 — 새 싱글톤을 만들지 않는다
- 타일 상태 변경은 반드시 Terrain Manager 함수를 거친다 — 다른 스크립트에서 Tilemap.SetTile 직접 호출 금지
- 상호작용 오브젝트는 기존 사과나무·동물이 쓰는 같은 베이스/인터페이스를 따른다
- 새 에셋은 `Assets/HappyHarvest/…` 아래 같은 종류 폴더에, 팀 전용 코드는 `Assets/_Team/Scripts`에 (샘플 업데이트 시 충돌 방지)
- 실외 씬은 팀에서 한 사람만 수정, 나머지는 프리팹·에셋·스크립트로 작업 — 타일맵 씬 병합 충돌은 사실상 복구 불가
- 시간 기반 로직(성장·마름)은 기존 방식(Update에서 경과 시간 비교)을 따르되, 새 타이머를 만들 때는 코루틴 대신 같은 패턴으로

**테스트 케이스 예시 (양식 D, 판매 상자 기준)**

| ID | 유형 | 전제 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| T-01 | 기능 | 밀 3개 보유, 금화 0 | 상자 클릭 | 인벤토리 0, 금화 = 3×밀 가격, HUD 갱신 |
| T-02 | 기능 | 호미 장착 | 상자 클릭 | 변화 없음, 콘솔 에러 없음 |
| T-03 | 회귀 | 상자 배치 후 | 경작→물→씨앗→수확 1회 전체 수행 | 1단계와 동일하게 동작 |
| T-04 | 회귀 | 금화 50 | 집 출입 후 복귀 | 금화 50 유지, 작물 수확 가능(기존 버그 재발 여부 확인) |
| T-05 | 경계 | 인벤토리 최대 스택 | 상자 클릭 | 전량 판매, 금화 오버플로 없음 |
| T-06 | 경계 | 밤 시간대 | 상자 클릭 | 낮과 동일 동작 (낮/밤 미연결 확인) |

자동화 시범 대상: 가격 계산(수량×단가)과 CropData 성장 단계 계산 — MonoBehaviour 없이 순수 함수로 분리해 Unity Test Framework EditMode 테스트 2개 작성.

**시간 함정 (사전 경고)**

- 실외 씬 병합 충돌 — 타일맵 데이터가 씬 파일에 직렬화되어 diff가 거대. 씬 담당 1인 규칙 엄수
- 새 작물 스프라이트의 임포트 설정(Pixels Per Unit, Filter, Secondary Textures) 불일치 → 크기·라이팅이 다르게 보임. 기존 작물 스프라이트의 프리셋을 복사
- 세이브 데이터가 구버전 구조로 남아 새 필드가 null → 개발 중 세이브 파일 삭제 위치를 안내
- `Camera.main.ScreenToWorldPoint` 기반 클릭 판정이 UI 위에서도 동작 → 상점 패널을 열면 뒤의 땅을 갈게 됨. UI 위 포인터 검사 추가 필요(#3 선택 팀 필수 안내)
- 낮/밤 연결(#5) 시 낮/밤 스크립트가 실외 씬에만 있어 실내에서 시간이 멈춤 → 시간 소유권을 GameManager로 옮길지 먼저 결정

## 5. 4단계 배포 (1주) — WebGL 온라인 배포

《배포 플랫폼》= **WebGL**. 싱글플레이 2D라 링크 하나로 플레이하게 하는 것이 가장 큰 가치이고, 패키지 43MB 수준이라 WebGL에 무리가 없다. 주의할 것은 2D 라이트·VFX Graph가 브라우저 GPU에서 무겁다는 점이다.

**빌드 특이사항**

- URP 2D Renderer 품질: WebGL용 URP Asset을 별도로 두고 라이트 볼륨 텍스처 해상도·그림자 품질을 낮춘다. 비 VFX는 파티클 수를 줄이거나 WebGL에서 끈다(품질 분기 스크립트 — 선택 과제)
- VFX Graph는 WebGL에서 컴퓨트 셰이더 제약이 있다 → 빌드 후 비·번개 효과가 보이는지 가장 먼저 확인. 안 보이면 해당 효과만 끄고 알려진 문제로 기록
- 텍스처: 스프라이트·노멀·마스크 맵이 3배로 들어가므로 압축 설정(ASTC/ETC2 대신 WebGL은 DXT 계열) 확인. 단색 마스크는 포럼 제안대로 최소 크기로
- 압축: Brotli + Decompression Fallback 켜기(GitHub Pages·itch.io는 서버 헤더 설정 불가)
- 입력: 터치 미지원이므로 스토어 페이지에 "PC 브라우저 전용" 명시(#9 구현 팀 제외)
- 세이브: WebGL은 IndexedDB에 저장되므로 브라우저를 바꾸면 사라짐 — 페이지에 안내

**목표치 《숫자》** (0주차 강사 빌드 측정값으로 확정): 빌드 폴더 60MB 이하 · 초기 로딩 20초 이내(일반 학교망) · 실외 씬 30fps 이상(내장 GPU 노트북)

**채널**: 필수 itch.io(WebGL 업로드, 페이지 커스터마이징, 통계 제공 — 5단계에 유리) · 선택 Unity Play 또는 GitHub Pages

**검증 추가 항목** (공통 체크리스트에 더함)

- [ ] Chrome·Edge·Safari에서 비·불·밤 라이트가 보이는가
- [ ] 실내 ↔ 실외 전환 시 멈춤 없이 페이드되는가
- [ ] 브라우저 새로고침 후 저장된 금화·작물이 복원되는가
- [ ] 스토어 페이지에 "Unity Happy Harvest 샘플 기반, 추가 기능: …" 와 라이선스 표기가 있는가

**선택 과제**: 터치 입력(#9) + 모바일 브라우저 대응 / 품질 자동 전환

## 6. 5단계 운영 (0.5주) — 플레이어 유입과 유지보수

농장 게임은 "편안한 루프"가 팔리는 장르라 15초 GIF에 심고→자라고→수확→판매까지의 한 바퀴가 들어가면 충분하다. Unity 샘플 원본과 똑같아 보이면 안 되므로 팀이 추가한 요소(상점·목표·새 작물)가 써네일에 보여야 한다.

- **홍보 차별점 《우리가 추가한 기능》**: "7일 안에 500골드" 같은 목표 한 줄 + 새 작물 이름 — 원본 샘플과의 차이가 한 문장에 드러나게
- **채널**: 학과 커뮤니티·동아리 → itch.io 태그(farming, cozy, unity) → 디스코드/스레드의 "농장 게임 피드백 요청" 글. 게임잼: itch.io의 소규모 cozy 게임 잼 또는 학과 자체 원내 잼
- **기록할 이벤트 3개**: 첫 수확까지 걸린 시간 / 첫 판매 시각 / 마지막 플레이 날짜(어느 날에 그만두는가). itch.io 통계(조회→플레이 전환율)와 함께 본다
- **피드백 폼 5문항 예시**: 무엇을 해야 하는지 바로 알았나 / 가장 재미있던 순간 / 그만둔 이유 / 버그 / 있었으면 하는 기능
- **유지보수 고유 점검**: 세이브 호환(새 필드 추가 시 구 세이브 로드 실패 방지 — 버전 필드 + 기본값) / 밸런스 수치(가격·성장 속도)는 코드가 아니라 데이터 에셋에 있으므로 핫픽스가 쉬움 — 이 점을 학생이 체감하게 / 브라우저별 VFX 미표시 보고 대응
- **후속 경로**: 학과 전시·게임의이해 교양 수업 시연작 / 캡스톤에서 같은 팀이 이어서 확장(퀀스트·NPC·계절)

## 7. 평가 배점과 제출 일정

공통 루브릭(양식 G)을 기본으로, Happy Harvest는 코드가 작아 분석 배점을 줄이고 구현·배포 배점을 늘린다.

| 항목 | 배점 | Happy Harvest 특화 기준 |
| --- | --- | --- |
| 1단계 분석 | 15 | 타일맵 레이어별 역할과 Terrain Manager·GameManager·CropInitializer 관계가 맞게 그려져 있는가 |
| 2단계 설계 | 20 | 기능 세트가 완결된 루프(사기→심기→팔기→목표)를 이루는가, 확장 방식이 데이터→컴포넌트→수정 순서를 따르는가 |
| 3단계 구현·테스트 | 35 | 필수 2개 동작 + 회귀 테스트(T-03·T-04) 통과 + 실외 씬 충돌 없이 머지 + 중간 점검 빌드 |
| 4단계 배포 | 20 | 목표치 달성한 WebGL 링크 + 2개 이상 브라우저 검증 + 스토어 페이지 |
| 5단계 운영 | 10 | 플레이어 10명 이상 + 피드백 로그 + v1.0.1 |

**제출 일정**: 1주 말 분석 3종 → 2주 말 명세서·가이드 → 3주 말 중간 점검 빌드 → 4주 말 최종 빌드·테스트 결과서 → 5주 말 공개 링크·배포 보고서 → 6주 피드백 로그·패치 노트·발표

**검토 시 확인 부탁**: 스크립트명(PlayerController, Terrain Manager, GameManager, CropInitializer, GroundData/CropData)은 공식 포럼·기술 문서에 언급된 것을 썼고, 인벤토리·낮/밤·상호작용 오브젝트의 실제 클래스명과 씨앗 획득 경로는 0주차에 프로젝트를 열어 확정해야 한다.
