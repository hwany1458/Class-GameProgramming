# Gem Hunter Match — Game Design Document

Nov 17, 2026 · @YongHwan Lee

Unity Learn의 GDD 템플릿 순서를 따라, 업로드된 Gem Hunter Match 프로젝트의 소스·씬·타일맵·데이터 에셋에서 읽은 사실만으로 쓴 "역설계" GDD다. 템플릿에 없는 것은 「확장 여지」로 표시했다. Happy Harvest(승패 없음) · Tower Defense(승패·저장 완성)와 나란히 놓으면 이 게임은 "승패는 있지만 그 결과가 아무 데도 남지 않는" 중간 지점이다.

## 1. 기본 정보

| 항목 | 내용 |
| --- | --- |
| **게임 이름** | Gem Hunter Match (Unity 공식 2D 샘플). 레벨 이름 필드는 셋 다 "Level"로 미설정 — 「확장 여지」 |
| **장르** | 타일 매치(매치-3) 퍼즐, 이동 수 제한형. 비교 대상: Candy Crush 계열의 "목표 수집 + 한정 이동" 포맷 (시간 제한 없음, 점수 없음) |
| **게임 요소** | ① 이웃한 보석 두 개를 드래그로 바꿔 같은 색 3개 이상을 맞춘다 ② 4개·5개·L자·2×2로 맞추면 보너스 젠이 생기고 그것을 터뜨린다 ③ 상자·밧줄 같은 장애물을 인접 매치로 부수고 푸는다 ④ 부스터를 써 막힌 곳을 뚫는다 ⑤ 20번의 이동 안에 목표(특정 색 N개 / 상자 N개)를 채운다 |
| **플레이어 수** | 1인. 턴 개념이 없는 실시간 보드 틱이라 같은 보드의 멀티는 어렵고, "같은 레벨을 더 적은 이동으로" 같은 비동기 경쟁이 현실적 |

## 2. 기술 사양

| 항목 | 내용 |
| --- | --- |
| **기술 형태** | 2D. URP 2D 렌더러, 2D Lights(보석에 빛 반사 션이더 그래프), Tilemap, VFX Graph(매치·폭발·코인·승패), UI Toolkit. Unity 6000.3.10f1 |
| **시점** | 정면 고정 카메라. 보드 크기에 맞춰 BorderMargin 0.3으로 자동 프레임. 세로(모바일) 비율 우선 |
| **플랫폼** | 모바일(iOS/Android) 우선 설계 — SafeArea 처리, 터치와 마우스 동일 경로. PC·WebGL도 그대로 동작. 이 강의에서는 WebGL 배포 |
| **언어** | C#. 레벨은 **타일맵 + 씬**, 데이터는 ScriptableObject(LevelList, BonusItem 5, ShopItem 7)와 GameManager 프리팹의 GameSettings. 보너스 모양은 프리팹 인스펙터(전용 에디터) |
| **기기** | 터치 화면 / 마우스. 키보드·게임패드 없음 |

코드 규모는 스크립트 27개로 세 샘플 중 가장 작지만 Board.cs 하나가 1,565줄이다. 확장 지점은 BonusGem 상속(새 보너스), Gem/Obstacle 상속(새 장애물), 타일 에셋(새 레벨)로 열려 있고, 규칙 변경은 Board를 직접 고쳐야 한다.

## 3. 게임플레이

**처음 3분 (Level1)**

메뉴에서 1을 누르면 화면이 어두워졌다 밝아지며 바다속 배경 위에 9칸 너비의 보석 판이 나타난다. 판 위에는 인어 초상과 네 개의 목표(파랑 8 · 보라 8 · 빨강 8 · 하양 8), 그리고 이동 20. 판 가운데에는 색이 정해진 보석 일곱 개가 십자로 박혀 있고, 나무 상자 세 개와 밧줄에 묶인 보석 두 개가 보인다. 파란 보석을 눌러 오른쪽으로 끌면 옆 보석과 자리를 바꾸고, 세 개가 반짝이다 터지며 위쪽 목표 아이콘으로 날아간다. 파랑 8이 5가 되고 이동은 19. 위에서 새 보석이 통통 떨어져 내리고, 운 좋게 연쇄가 한 번 더 터진다. 맞는 게 없는 쪽으로 끌면 보석이 갔다가 돌아오고 이동은 줄지 않는다.

빨강 네 개를 가로로 맞추자 그 자리에 세로 줄무늬가 그려진 보석이 남는다. 다음 수에 그것을 매치에 얽으면 로켓이 세로 한 줄을 훑고 지나가고 코인이 한 개 떠오른다. 상자 옆에서 매치를 만들 때마다 상자에 금이 가고, 세 번째에 부서진다. 이동이 3이 되면 인어가 초조한 표정을 짓는다. 고민하며 8초를 멈추면 보석 하나가 빛나며 어느 쪽으로 밀라고 알려 준다. 하양이 2개 모자란 채 이동 0 — 보드가 멈추자 인어가 고개를 떨구고 LOSE. 다시 하기 버튼.

**게임플레이 아웃라인**

| 항목 | 내용 |
| --- | --- |
| 앱 실행 | Init(빈 씬) → Main: 레벨 버튼 1·2·3뿐. 타이틀·옵션·종료 없음 |
| 옵션 | 레벨 안 설정 메뉴: Main/Music/SFX 볼륨 (저장됨) |
| 스토리 | 없음. 인어 캐릭터가 표정으로 반응할 뿐 — 「확장 여지」 |
| 모드 | 레벨 3개, 모두 "이동 20 안에 목표". 시간제·무한·점수제 없음 — 「확장 여지」 |
| 게임 요소 | 보석 6색, 보너스 젠 5종, 장애물 2종(상자·밧줄), 부스터 4종, 상점 |
| 레벨 | Level1 85칸 색 목표 / Level2 60칸 상자 6 / Level3 96칸 하트, 전부 고정 배치. 잠금 없음 |
| 조작 | 누르고 끌어 스와프(터치 = 마우스). 부스터는 버튼 후 칸 탭 |
| 승리 | 모든 목표 카운트 0 (이동이 남아 있든 마지막 수든). 보드가 멈춘 뒤 판정 |
| 패배 | 이동 0이 되고 보드가 멈추었는데 목표가 남음 |
| 종료 | WIN/LOSE 타이틀 + 인어 애니메이션 + VFX → Replay / Select Level. 승리해도 다음 레벨로 바로 가는 버튼 없음 |
| 왜 재미있나 | "한 수로 얼마나 많이 터뜨리나"의 계획 — 보너스를 만들고 아끼다가 목표 색이 많은 줄에 쓰는 재미, 그리고 보석이 쪼개지고 튜고 날아가는 촉감(VFX·커브에 설정의 절반이 할애되어 있다) |

**핵심 기능**

- 드래그 스와프와 헛스와프 되돌리기 — 이동을 낭비하지 않는다
- 매치 모양이 다른 보너스를 만든다: 가로 4 → 세로 로켓, 세로 4 → 가로 로켓, 2×2 → 소형 폭탄, L자 → 대형 폭탄, 5 일렬 → 컴러 제거
- 보너스끼리 스와프하면 둘 다 발동
- 인접 매치로 부수는 상자(체력 3), 매치로 푸는 밧줄(2단계)
- 타일 팔레트로 그리는 보드 — 하트 모양 같은 자유 형태, 보드 안쪽 스포너
- 8초 뒤 힌트, 인어 캐릭터의 상황별 반응, 터치 제일 설계

## 4. 디자인 문서

**디자인 지침** (샘플에서 읽어낼 수 있는 제약과 목표)

- 전연령, 밝은 바다속 판타지. 실패를 벌하지 않는다(생명이 줄지 않고, 헛스와프도 이동을 소모하지 않는다).
- 한 판 1\~3분, 한 손 세로 화면. 시간 압박 없음 — 압박은 이동 수로만.
- 플레이어의 개입은 **스와프와 부스터 사용** 단 두 가지. 나머지(낙하·연쇄·보너스 발동)는 보드가 알아서 한다.
- 레벨은 코드 없이 타일로만 만든다. 보너스·장애물은 상속으로 더한다. Board.cs는 가능한 건드리지 않는다.
- 모바일 먼저: 터치로 다 되어야 하고 세로 화면에 들어가야 한다.
- 한 줄 목표: "보석이 터지는 순간이 기분 좋아야 한다" — 설정의 절반이 커브와 VFX인 이유.

**게임 디자인 정의**

| 항목 | 정의 | 구현 |
| --- | --- | --- |
| **승리** | LevelData.Goals의 모든 Count가 0. 달성 순간 별 +1, 입력 차단, 보드가 멈추면 WIN. 남은 이동 수는 아무 데도 쓰이지 않는다 | LevelData.Matched → OnAllGoalFinished, GameManager.WinStar, Board.FinalStretch |
| **패배** | RemainingMove 0이 되고 보드가 멈추었을 때 GoalLeft > 0. 마지막 수의 연쇄로 목표를 채우면 승리가 우선 | LevelData.Moved → OnNoMoveLeft, UIHandler.ShowEnd |
| **이동** | 매치를 만드는 스와프만 1 소모. 헛스와프·부스터 사용은 0. 보너스끼리 스와프는 1 | Board SwapStage, LevelData.Moved |
| **레벨 전환** | 종료 화면의 Select Level → Main, Replay → 같은 씬. 레벨 사이에 이어지는 것은 코인·부스터·별(메모리)이고 앱을 끄면 볼륨만 남는다 | UIHandler, GameManager |
| **핵심 초점** | "이번 수로 목표 색을 몇 개 지울 수 있나, 보너스를 만들 것인가 쓸 것인가". 이동 20 ÷ 목표 32개(Level1)는 수당 1.6개 — 3매치만으로는 부족하고 연쇄·보너스가 필요하다 | LevelData.MaxMove / Goals |
| **경제** | 코인은 4매치 이상에서 4번째 보석부터 1개. 상점 20\~150. 시작 부스터 4종 × 2 | GameManager.ChangeCoins, ShopItem |
| **보드 규칙** | 빈 칸은 위에서 떨어져 채워지고, 스포너 칸만 새 보석을 만든다. 대각선 낙하 없음 — 스포너 없는 열은 비어 간다 | Board 낙하 틱, GemSpawner |

Happy Harvest와 달리 승패가 있고, Tower Defense와 달리 그 결과가 저장되지 않는다. 그래서 이 GDD의 「확장 여지」는 규칙이 아니라 **진행과 보상**(별의 쓰임새, 생명의 의미, 레벨 잠금, 저장)에 몰려 있다.

판정이 네 개인데 그중 두 개(매치? · 연쇄?)는 보드가, 두 개(목표 · 이동)는 LevelData가 한다. 승패 판정은 이동이 0이 되는 순간이 아니라 ⑧ 낙하가 완전히 멈춘 뒤에 내려진다 — 마지막 수의 연쇄로 이길 수 있는 이유다.

## 6. 플레이어 정의

**플레이어 정의**: 보드 밖에서 보석을 옮기는 손. 화면 위의 인어 캐릭터는 플레이어가 아니라 플레이어의 상황을 표정으로 보여 주는 거울(Idle · LowMove · Win · Lose)이다. 할 수 있는 행동은 두 가지 — 이웃한 보석을 바꾸기, 부스터를 고른 뒤 칸 고르기. 템플릿의 Health / Weapons / Actions는 각각 남은 이동 / 부스터 / 위 두 행동으로 대응한다.

**플레이어 속성** (각 속성이 바뀔 때의 피드백 포함)

| 속성 | 범위·초기값 | 바뀜 때 | 피드백 |
| --- | --- | --- | --- |
| 남은 이동 | 20 → 0 (레벨마다 리셋) | 매치가 생긴 스와프마다 −1 | MoveCounter 숫자. 3 이하가 되는 순간 인어 LowMove 애니메이션, 배경 어두워짐(DarkenBackground) |
| 목표 카운트 × n | Level1·3: 4색 각 8 / Level2: 상자 6 | 해당 보석이 삭제될 때마다 −1 | 보석이 목표 아이콘으로 날아가는 연출(MatchFlyCurve), 숫자 갱신, 0이 되면 체크 표시 |
| 코인 (영속, 미저장) | 0 이상 | 4매치 이상의 4개째부터 +1, 상점 − | 코인 VFX가 상단 바로 날아감(CoinFlyCurve), CoinLabel 갱신, 구매 버튼 활성/비활성 |
| 부스터 보유 수 × 4 | 각 2 | 사용 −1, 구매 +1 | 하단 버튼의 숫자. 0이면 버튼 비활성. 선택 중에는 보드가 어두워짐 |
| 생명 (영속) | 5 | 구매 +1만. **감소 없음** | LiveLabel — 바뀌 일이 거의 없다 |
| 별 (영속, 미저장) | 0 | 승리 +1 | StarLabel. 어디에도 쓰이지 않음 |
| 선택 상태 | 없음 / 누른 칸 / 부스터 대기 | 누름·놓음·부스터 버튼 | 누른 칸에 Hold VFX, 손가락을 따라오는 트레일 VFX |

**플레이어 보상** (긍정적 영향을 주는 것)

| 보상 | 효과 | 얻는 방법 |
| --- | --- | --- |
| 보너스 젠 (로켓 ×2 · 소형 폭탄 · 대형 폭탄 · 컴러) | 한 번에 한 줄 / 범위 / 한 색 전부 삭제 — 목표에 셌다 | 4일렬 · 2×2 · L자 · 5일렬 매치. 두 보너스를 스와프하면 둘 다 발동 |
| 연쇄 | 이동 소모 없이 추가 삭제 | 낙하 후 저절로 생기는 매치 |
| 코인 | 상점 구매 | 4개 이상 매치 |
| 부스터 | 원하는 칸에 보너스 젠 즉시 발동, 이동 소모 없음 | 시작 각 2 + 상점(20 · 30 · 30 · 50 · 150) |
| 힌트 | 가능한 스와프 하나를 빛으로 알려 줌 | 8초 무입력 |
| 생명 · 별 | 실질 효과 없음 | 「확장 여지」 |
| 연속 매치 보너스 · 점수 · 남은 이동 환산 · 일일 보상 | 없음 | 「확장 여지」 |

## 7. 사용자 인터페이스

**조작** (Input System: ClickAction + ClickPosition, 터치와 마우스 동일)

| 행동 | 터치 / 마우스 | 비고 |
| --- | --- | --- |
| 스와프 | 보석을 누른 채 이웃 방향으로 끌고 놓기 (이동 0.5 이상, 상하좌우 중 큰 쪽) | 두 번 탭 방식 아님. 놓기 전에는 Hold VFX만 |
| 부스터 | 하단 버튼 탭 → 보드가 어두워짐 → 대상 칸 탭 | 빈 칸 탭은 무시(취소 아님 — 취소 방법 없음) |
| 메뉴 / 상점 | 상단 버튼 | 설정: 볼륨 3종, 레벨 선택으로, 닫기 |
| 종료 화면 | Replay / Select Level | — |
| 키보드 · 게임패드 · 일시정지 | 없음 | 「확장 여지」 |

**HUD** (UI Toolkit, UIDocument 프리팹 하나, SafeArea 적용): 상단 바에 코인 · 생명 · 별 · 메뉴 · 상점. 그 아래 인어 초상(별도 카메라 렌더 텍스처)과 목표 아이콘들, 남은 이동. 가운데 보드. 하단 부스터 4개와 보유 수. 상점은 스크롤 목록(아이콘·이름·가격·구매 버튼). 모두 UXML 템플릿을 코드에서 인스턴스화한다.

**화면에 없는 정보**: 다음에 떨어질 보석, 점수·콤보, 이 레벨의 별 조건, 부스터 선택 취소 방법, 마지막 수임을 강조하는 표시(인어 표정과 배경 어두워짐이 유일한 단서).

**최악의 레이아웃 검토**: 세 샘플 중 유일하게 터치만으로 전부 할 수 있고, 마우스만으로도 전부 할 수 있다. 가로 화면(PC 브라우저)에서는 세로 레이아웃이 양옆에 여백을 남기고 보드가 작아진다 — WebGL 배포 시 캔버스 비율 고정이나 가로 레이아웃이 필요하다. 키보드만 있으면 플레이 불가(접근성 과제). 작은 화면에서 부스터 버튼이 보드 맨 아랫줄과 가까워 오탭 가능성이 있다.
