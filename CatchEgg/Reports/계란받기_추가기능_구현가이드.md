# 계란받기 추가 기능 구현 가이드

> 「계란받기 유사 게임 기능 작성」 과제에서 학생들이 제안한 기능 40개에 대해, 기존 실습 코드(CsManager, CsEgg, CsBomb, CsBucket, CsBird, CsSky)를 기준으로 **구현 방향**과 **구현 방법**을 정리한 문서.
> 기능 ID(A-1 ~ J-4)는 학생 배포용 「추가 기능 카탈로그」와 같다.

## 문서 구성

- **0장 공통 기반** — 여러 기능이 함께 쓰는 구조를 먼저 만든다. 대부분의 기능이 이 위에서 몇 줄로 끝난다.
  - 게임 상태 확장
  - 게임 오버 일원화
  - 시간 제한 효과
  - 가중치 생성표
  - 아이템 기본 클래스
  - 속도 기반 바구니 이동
- **1장 기능별 구현** — 각 기능을 네 항목으로 설명한다.
  - **구현 방향**: 설계 결정과 규칙
  - **구현 방법**: 수정할 스크립트, 단계, 코드
  - **확인할 점**: 테스트와 밸런스
- **2장 기능 간 의존 관계와 권장 구현 순서**

## 0. 공통 기반

### 0-1. 게임 상태 확장 (CsManager)

현재 게임 상태는 `hit`, `miss`, `isDead` 세 개뿐이다. 추가 기능에 필요한 상태를 한곳에 모으고, 다른 스크립트가 CsManager의 함수·코루틴을 부를 수 있도록 **자기 참조(inst)** 를 둔다.

```csharp
using System.Collections.Generic;   // 파일 상단에 추가

// ---- 추가 상태 변수 ----
static public CsManager inst;           // 다른 스크립트에서 CsManager 함수 호출용
static public int score = 0;            // 점수 (hit는 받은 개수로 유지)
static public int combo = 0;            // 현재 콤보 (A-1)
static public int maxCombo = 0;         // 이번 판 최대 콤보
static public int maxLife = 5;          // 놓쳐도 되는 계란 수 (E-1)
static public int scoreMultiplier = 1;  // 점수 배율 (C-4)
static public float slowFactor = 1f;    // 아이템 감속 배율 (C-1)
static public float levelFactor = 1f;   // 난이도 가속 배율 (D-1, D-2)
static public bool isFever = false;     // 피버 상태 (A-4)
static public float FallFactor => slowFactor * levelFactor;   // 낙하물이 실제로 곱할 값

public Transform bucket;                // 바구니 루트 오브젝트 (인스펙터에서 연결)

void Awake() { inst = this; }
```

`InitStage()`에 초기화를 추가한다. static 변수는 씬을 다시 불러와도 값이 남기 때문에 **반드시** 여기서 되돌려야 한다.

```csharp
score = 0; combo = 0; maxCombo = 0;
scoreMultiplier = 1; slowFactor = 1f; levelFactor = 1f; isFever = false;
```

계란·폭탄의 `Update()`는 배율을 곱하도록 한 줄 바꾼다.

```csharp
float amtMove = speed * CsManager.FallFactor * Time.smoothDeltaTime;
```

### 0-2. 게임 오버 처리 일원화

지금은 CsEgg와 CsBomb가 각자 `isDead = true`와 바구니 제거를 한다. 여기에는 두 가지 문제가 있다.

- CsEgg는 `Find("Bucket")`을 쓰므로 계층의 이름이 다르면 바구니를 찾지 못한다.
- 기록 저장처럼 **게임 오버 순간 한 번만** 해야 할 일을 넣을 곳이 없다.

그래서 게임 오버 처리를 한 함수로 모은다.

```csharp
// CsManager
bool isNewRecord = false;               // B-2

static public void GameOver()
{
    if (isDead) return;                 // 두 번 호출되어도 한 번만 실행
    isDead = true;
    if (inst.bucket) Destroy(inst.bucket.gameObject);
    inst.SaveRecord();                  // B-1, B-3
}
```

- **CsEgg:** `CsManager.isDead = true; Destroy(GameObject.Find("Bucket"));` 두 줄을 `CsManager.GameOver();`로 바꾼다.
- **CsBomb:** `CsManager.isDead = true;`와 `Destroy(coll.transform.root.gameObject);`를 `CsManager.GameOver();`로 바꾼다.

게임 오버 이후에 떨어진 계란이 점수·miss를 바꾸지 않도록 CsEgg `OnCollisionEnter()` 맨 앞에 다음을 넣는다.

```csharp
if (CsManager.isDead) { Destroy(gameObject); return; }
```

### 0-3. 시간 제한 효과 (코루틴 관리)

아이템, 피버, 스턴, 디버프는 모두 "시작 → N초 유지 → 종료" 구조다. 효과마다 코루틴을 따로 만드는 대신, 이름(key)으로 관리하는 함수 하나를 둔다. 같은 효과를 다시 얻으면 남은 시간이 **갱신**된다.

```csharp
// CsManager
Dictionary<string, Coroutine> effects = new Dictionary<string, Coroutine>();
Dictionary<string, float> effectEnd = new Dictionary<string, float>();

/// onStart는 "값을 절대값으로 설정"하는 코드여야 한다 (예: slowFactor = 0.5f).
/// 갱신 시 다시 호출되므로 "*= 1.5f" 같은 누적 코드는 쓰지 않는다.
public void RunTimed(string key, float duration, System.Action onStart, System.Action onEnd)
{
    if (effects.TryGetValue(key, out Coroutine c) && c != null) StopCoroutine(c);
    onStart();
    effectEnd[key] = Time.time + duration;
    effects[key] = StartCoroutine(TimedRoutine(key, duration, onEnd));
}

IEnumerator TimedRoutine(string key, float duration, System.Action onEnd)
{
    yield return new WaitForSeconds(duration);
    onEnd();
    effects.Remove(key);
    effectEnd.Remove(key);
}

public float Remaining(string key)      // UI에 남은 시간 표시용
{
    return effectEnd.TryGetValue(key, out float t) ? Mathf.Max(0, t - Time.time) : 0;
}
```

사용 예: `CsManager.inst.RunTimed("slow", 7f, () => CsManager.slowFactor = 0.5f, () => CsManager.slowFactor = 1f);`

### 0-4. 가중치 생성표

황금 계란, 특수 계란, 테마 교체, 아이템은 모두 "여러 프리팹 중 확률로 하나 고르기"다. 인스펙터에서 프리팹과 가중치를 넣을 수 있는 표를 만든다.

```csharp
// CsManager 클래스 바깥(또는 안)에 선언
[System.Serializable]
public class SpawnEntry
{
    public Transform prefab;
    public float weight = 1f;           // 상대 확률 (일반 90, 황금 8, 무지개 2 → 90%, 8%, 2%)
}

// CsManager
public SpawnEntry[] eggTable;           // 비어 있으면 기존 egg 사용

Transform Pick(SpawnEntry[] table)
{
    float total = 0;
    foreach (var e in table) total += e.weight;
    float r = Random.value * total;
    foreach (var e in table)
    {
        if (r < e.weight) return e.prefab;
        r -= e.weight;
    }
    return table[table.Length - 1].prefab;
}
```

`MakeEgg()`의 `Instantiate(egg);`를 다음으로 바꾼다.

```csharp
Instantiate(eggTable.Length > 0 ? Pick(eggTable) : egg);
```

계란 종류별 차이는 CsEgg에 변수를 두고 **프리팹 베리언트**(Prefab Variant)마다 값을 바꿔 준다. 방법은 계란 프리팹 우클릭 → Create → Prefab Variant다.

```csharp
// CsEgg
public string eggId = "normal";         // 종류 식별 (H-1 도감)
public int point = 1;                   // 기본 점수 (A-2, A-3)
public float speedMul = 1f;             // 낙하 속도 배율 (A-3)
public bool triggersFever = false;      // 받으면 피버 발동 (A-4)
```

`SetPosition()`의 속도 줄을 `speed = Random.Range(3, 5f) * speedMul;`로 바꾼다.

### 0-5. 아이템 기본 클래스

아이템은 "계란처럼 떨어지고, 바구니에 닿으면 효과 발동, 바닥에 닿으면 사라짐"이 공통이다. 추상 클래스로 공통 부분을 만들고, 아이템마다 `Apply()`만 작성한다.

```csharp
// CsItem.cs
using UnityEngine;

public abstract class CsItem : MonoBehaviour
{
    public float duration = 7f;         // 효과 지속 시간
    public AudioClip sndGet;            // 획득 효과음
    float speed;

    void Start()
    {
        speed = Random.Range(3, 4f);
        transform.position = new Vector3(Random.Range(-8.5f, 8.5f), Random.Range(12, 14f), -2);
    }

    void Update()
    {
        transform.Translate(Vector3.down * speed * CsManager.FallFactor * Time.smoothDeltaTime, Space.World);
    }

    void OnCollisionEnter(Collision coll)
    {
        string tag = coll.transform.tag;
        if (tag == "SAFE" || tag == "BUCKET")
        {
            if (!CsManager.isDead)
            {
                Apply();
                if (sndGet) AudioSource.PlayClipAtPoint(sndGet, transform.position);
            }
            Destroy(gameObject);
        }
        else if (tag == "GROUND")
        {
            Destroy(gameObject);
        }
    }

    protected abstract void Apply();    // 아이템별 효과
}
```

CsManager에는 아이템 생성을 추가한다.

```csharp
public SpawnEntry[] itemTable;
float ITEM_DELAY = 12f;                 // 아이템 평균 등장 간격(초)
float itemDelay;                        // InitStage()에서 itemDelay = ITEM_DELAY;

void MakeItem()                         // Update()의 if (!isDead) 블록 안에서 호출
{
    if (itemTable.Length == 0) return;
    itemDelay -= Time.deltaTime;
    if (itemDelay <= 0)
    {
        Instantiate(Pick(itemTable));
        itemDelay = ITEM_DELAY * Random.Range(0.7f, 1.3f);
    }
}
```

**아이템 프리팹 만드는 법**
- 오브젝트: Sphere 또는 Quad
- 콜라이더와 Rigidbody(Use Gravity 해제)
- 태그 **ITEM** 추가
- 해당 아이템 스크립트 부착

**충돌 레이어 정리 (권장)**

계란·폭탄·아이템끼리 부딪혀 튕기지 않도록 설정한다.

1. 레이어 **Falling**을 만들어 세 종류 프리팹에 지정한다.
2. Project Settings → Physics → Layer Collision Matrix에서 Falling × Falling 체크를 끈다.

단, 폭탄이 계란을 깨는 규칙을 유지하려면 폭탄만 다른 레이어로 둔다.

### 0-6. 속도 기반 바구니 이동 (CsBucket)

현재 바구니는 마우스 위치로 **순간이동**한다. 이 방식에서는 "이동 속도"라는 개념이 없으므로 다음 기능이 의미를 가지려면 속도 기반 이동이 먼저 필요하다.

- C-3 이동 속도 증가
- E-2 감속 디버프
- F-2 대시
- F-3 관성
- D-5 도달 가능 스폰

마우스 조작은 유지하되, 목표 위치로 **최대 속도 이하로** 따라가게 바꾼다.

```csharp
// CsBucket
static public CsBucket inst;            // 다른 스크립트에서 바구니 정보 참조용
public float moveSpeed = 12f;           // 기본 이동 속도 (유닛/초)
static public float speedMul = 1f;      // 버프 배율 (C-3, A-4)
static public float debuffMul = 1f;     // 디버프 배율 (E-2) — 버프와 분리해 서로 덮어쓰지 않게 함
static public bool isStunned = false;   // 스턴 여부 (E-3)
static public float MaxSpeed => inst ? inst.moveSpeed * speedMul * debuffMul : 0f;   // D-5
float targetX;

void Awake() { inst = this; }
void Start() { targetX = transform.position.x; }

void Update()
{
    if (CsManager.isDead || isStunned) return;

    if (Input.GetButton("Fire1"))
    {
        Vector3 mousePos = Input.mousePosition;
        mousePos.z = 24;
        targetX = Camera.main.ScreenToWorldPoint(mousePos).x;
    }

    float x = Mathf.MoveTowards(transform.position.x, targetX, MaxSpeed * Time.deltaTime);
    x = Mathf.Clamp(x, -8.5f, 8.5f);
    transform.position = new Vector3(x, 0, -2);
}
```

static 변수 `speedMul`, `debuffMul`, `isStunned`는 CsManager `InitStage()`에서 각각 1f, 1f, false로 초기화한다.

`moveSpeed`를 아주 크게(100 이상) 주면 기존의 순간이동 방식과 거의 같아지므로, 두 조작감을 비교하는 실습으로도 쓸 수 있다.

## 1. 기능별 구현

### A. 점수 · 보상

#### A-1. 콤보 시스템
*제안: 김동현 · 김민준 · 정종헌 · 김유경 · 이승민 · 이현수 · 유상현(구현)*

**구현 방향**
- 계란을 받으면 콤보 +1, 바닥에 떨어뜨리면 0이 된다.
- 폭탄이 공중에서 계란을 깬 경우는 플레이어 실수가 아니므로 콤보를 유지한다.
- 보너스 계산 방식은 두 가지 중 하나를 고른다.
  - **가산형** (유상현 방식): `기본점수 + min(콤보, 30) × 10`. 이해하기 쉽고 상한이 있어 점수 폭주가 없다.
  - **배수형** (정종헌 방식): 10콤보 이상이면 ×1.5. 구간이 분명해 "10콤보 달성"이 목표가 된다.
- 콤보가 2 이상일 때만 화면에 표시하고, 늘어날 때 잠깐 크게 보여 준다.

**구현 방법**
1. CsManager에 점수 계산 함수를 만든다. (가산형 예시)
   ```csharp
   static public void AddScore(int point)
   {
       combo++;
       maxCombo = Mathf.Max(maxCombo, combo);
       int bonus = Mathf.Min(combo, 30);                  // 콤보 보너스 상한 30
       score += (point + bonus) * scoreMultiplier;
   }

   static public void BreakCombo() { combo = 0; }
   ```
2. CsEgg `OnCollisionEnter()`를 수정한다.
   - SAFE: `CsManager.hit++;` 다음 줄에 `CsManager.AddScore(point);`
   - GROUND: `CsManager.miss++;` 다음 줄에 `CsManager.BreakCombo();`
3. `OnGUI()`에 콤보 표시를 추가한다. 늘어나는 순간 커졌다 줄어드는 효과를 넣는다.
   ```csharp
   int lastCombo = 0; float comboPop = 0;          // 클래스 멤버

   // OnGUI() 안
   if (combo != lastCombo) { if (combo > lastCombo) comboPop = 1f; lastCombo = combo; }
   comboPop = Mathf.Max(0, comboPop - Time.deltaTime * 3);
   if (combo >= 2) {
       int size = 36 + (int)(comboPop * 20);
       GUI.Label(new Rect(w - 80, 70, 220, 60),
           "<color='orange'><size='" + size + "'>" + combo + " COMBO</size></color>");
   }
   ```
4. 점수 표시를 `hit` 대신 `score`로 바꾸고, 받은 개수는 작게 병기한다.

**확인할 점**
- `OnGUI`는 한 프레임에 여러 번 호출되어 `comboPop`이 빨리 줄어들 수 있다. 느리게 보이면 감소 코드를 `Update()`로 옮긴다.
- 30콤보 이후 점수 증가 속도가 적절한지 확인한다. 상한이 없으면 후반 점수가 기하급수적으로 커진다.

#### A-2. 황금 · 특수 계란
*제안: 문헌민 · 정종헌 · 이승민 · 이현수 · 강미정 · 김유경 · 이건희*

**구현 방향**
- 일반 계란 프리팹의 **베리언트**로 만들어 모양·스크립트는 공유하고 색, 점수, 효과만 다르게 한다.
- 등장 확률은 일반 90%, 황금 8%, 무지개 2% 정도에서 시작한다. 한 판(약 2분, 계란 120개)에 황금 10개, 무지개 2개 정도가 나오는 수준이다.
- 특수 계란은 **멀리서도 구분**되어야 한다.
  - 색: 금색 머티리얼
  - 크기: 약간 크게
  - 반짝임: 작은 파티클 부착

**구현 방법**
1. 계란 프리팹 → Create → Prefab Variant로 `EggGold`를 만든다.
2. 머티리얼을 복제해 색을 금색(예: #FFD34D)으로 바꾸고, CsEgg 값을 `eggId = "gold"`, `point = 5`로 설정한다.
3. (선택) 자식에 Sparks 파티클을 추가한다. 폭탄의 도화선 파티클을 복사해 색만 노랗게 바꾸면 된다.
4. GameManager의 `eggTable`에 일반(90)과 황금(8)을 등록한다. (0-4 가중치 생성표)
5. 황금 계란을 받을 때 전용 효과음과 "+5" 팝업(J-4)을 띄운다.
   ```csharp
   // CsEgg SAFE 처리
   AudioSource.PlayClipAtPoint(point > 1 && sndSpecial ? sndSpecial : sndCatch, transform.position);
   ```

**확인할 점**
- 깨진 계란 연출(EggBroken)은 텍스처를 `egg_broken`으로 바꾸므로, 황금 계란이 깨져도 일반 깨진 계란으로 보인다. 필요하면 `public Texture brokenTexture` 변수를 두어 종류별로 지정한다.

#### A-3. 등급별 점수 · 낙하 속도 차등
*제안: 정종헌 · 김유경*

**구현 방향**
- **위험과 보상을 짝지운다.** 점수가 높은 계란일수록 빠르게 떨어져, 받을지 말지 판단하게 만든다.

| 등급 | eggId | point | speedMul | 가중치 |
|---|---|---|---|---|
| 일반 | normal | 1 | 1.0 | 80 |
| 무늬 | pattern | 2 | 1.15 | 15 |
| 황금 | gold | 5 | 1.4 | 5 |
| (초란) | small | 1 | 0.8 | 선택 — 작고 느린 계란, 크기로 난이도 조절 |

**구현 방법**
1. A-2와 같은 방식으로 등급별 베리언트를 만들고 `point`, `speedMul`을 표대로 설정한다. `speedMul`은 0-4에서 `SetPosition()`에 이미 반영되어 있다.
2. 크기 차이를 둘 경우 베리언트의 Transform Scale을 바꾼다. 콜라이더도 함께 커지거나 작아지므로 난이도에 영향이 있다.

**확인할 점**
- `speedMul`이 1.5를 넘으면 D-1 가속과 겹쳐 후반에 받을 수 없는 속도가 될 수 있다. 최종 낙하 속도는 `기본 3~5 × speedMul × FallFactor`로 계산된다.

#### A-4. 피버타임
*제안: 문헌민 · 김유경*

**구현 방향**
- **발동 조건:** 황금·무지개 계란을 받으면 발동한다. (다른 안: 20콤보 달성 시)
- **효과** (문헌민안 + 김유경안 결합)
  - 3~5초간 바구니 1.5배 확대
  - 이동 속도 1.5배
  - 폭탄 무효 (닿으면 작은 폭발로 사라지고 게임 오버 안 됨)
  - 점수 2배
- **표시:** 피버 중임을 분명히 알린다.
  - 화면 가장자리 색 변화
  - "FEVER!" 문구와 남은 시간 막대
  - 배경음악 피치 상승

**구현 방법**
1. 무지개·황금 계란 베리언트에서 `triggersFever = true`로 설정한다.
2. CsEgg SAFE 처리에 발동 코드를 추가한다.
   ```csharp
   if (triggersFever) CsManager.inst.StartFever(4f);
   ```
3. CsManager에 피버 함수를 만든다. (0-3 RunTimed 사용)
   ```csharp
   public void StartFever(float duration)
   {
       RunTimed("fever", duration,
           () => {
               isFever = true;
               scoreMultiplier = 2;
               CsBucket.speedMul = 1.5f;
               if (bucket) bucket.localScale = new Vector3(1.5f, 1f, 1.5f); // 높이는 유지 (원래 Scale이 1일 때 기준)
               Camera.main.GetComponent<AudioSource>().pitch = 1.2f;
           },
           () => {
               isFever = false;
               scoreMultiplier = 1;
               CsBucket.speedMul = 1f;
               if (bucket) bucket.localScale = Vector3.one;
               Camera.main.GetComponent<AudioSource>().pitch = 1f;
           });
   }
   ```
4. CsBomb의 BUCKET/SAFE 충돌 처리 맨 앞에 피버 분기를 넣는다.
   ```csharp
   if (CsManager.isFever) {
       Instantiate(expSmall, transform.position, Quaternion.identity);
       Destroy(gameObject);
       return;
   }
   ```
5. `OnGUI()`에서 `isFever`일 때 "FEVER!"와 남은 시간 막대를 그린다. 남은 시간은 `Remaining("fever") / 4f` 비율로 폭을 계산한다.

**확인할 점**
- 바구니 원래 Scale이 1이 아니면 `Start()`에서 원래 값을 저장해 두고 그 배수로 설정한다.
- 바구니를 키우면 x 이동 범위(±8.5) 끝에서 화면 밖으로 삐져나올 수 있다. 피버 중에는 범위를 ±8로 줄이는 것을 고려한다.
- 피버 효과와 C-2(바구니 확대), C-4(점수 2배) 아이템이 동시에 끝날 때 서로 값을 덮어쓰지 않는지 확인한다. 같은 값을 여러 효과가 바꾸는 경우 key를 공유하거나, 배율을 효과별로 따로 두고 곱해서 쓴다.

#### B-1. 최고 점수 저장 · 갱신
*제안: 김동현 · 이승민*

**구현 방향**
- 게임 오버 순간 **한 번만** 이번 점수를 최고 기록과 비교해 저장한다. 0-2의 `GameOver()`에서 호출하므로 중복 저장 걱정이 없다.

**구현 방법**
```csharp
// CsManager
int bestScore;

// InitStage()
bestScore = PlayerPrefs.GetInt("BestScore", 0);
isNewRecord = false;

// GameOver()에서 호출
void SaveRecord()
{
    if (score > bestScore)
    {
        bestScore = score;
        isNewRecord = true;
        PlayerPrefs.SetInt("BestScore", bestScore);
        PlayerPrefs.Save();             // 앱 강제 종료 대비 즉시 기록
    }
    SaveRanking();                      // B-3을 구현한 경우
}

// OnGUI()
GUI.Label(new Rect(20, 65, 200, 30), "<size='20'>BEST " + bestScore + "</size>");
```

**확인할 점**
- 테스트 중 기록을 지우려면 에디터 메뉴 Edit → Clear All PlayerPrefs를 사용하거나, 디버그 키에 `PlayerPrefs.DeleteAll()`을 연결한다.
- WebGL 빌드에서는 PlayerPrefs가 브라우저 저장소에 기록된다. 브라우저 데이터를 지우면 사라진다.

#### B-2. New Record 연출
*제안: 이승민*

**구현 방향**

- (선택) 플레이 중 최고 기록을 **넘는 순간**에도 짧게 알려 주면 긴장감이 커진다.

public AudioClip sndRecord;
bool recordAlerted = false;             // InitStage()에서 false

// OnGUI()의 if (isDead) 블록 안
if (isNewRecord) {

#### B-3. 닉네임 · 로컬 TOP 5 순위표
*제안: 김주헌(구현)*

**구현 방향**
- 시작 화면(J-3)에서 닉네임을 입력하고, 게임 오버 시 {이름, 점수, 생존 시간}을 목록에 넣어 정렬한 뒤 상위 5개만 저장한다.
- 정렬 기준: 점수 내림차순, 동점이면 생존 시간이 긴 순. 김주헌안을 그대로 따른다.
- 저장은 목록을 JSON 문자열로 바꿔 PlayerPrefs 한 키에 넣는다.

**구현 방법**
```csharp
// Record.cs (MonoBehaviour 아님)
using System.Collections.Generic;

[System.Serializable] public class Record { public string name; public int score; public float time; }
[System.Serializable] public class RecordList { public List<Record> items = new List<Record>(); }
```
```csharp
// CsManager
static public string playerName = "PLAYER";
RecordList ranking;

// InitStage()
ranking = JsonUtility.FromJson<RecordList>(PlayerPrefs.GetString("Ranking", "{}")) ?? new RecordList();
if (ranking.items == null) ranking.items = new List<Record>();

void SaveRanking()
{
    ranking.items.Add(new Record { name = playerName, score = score, time = stageTime - startTime });
    ranking.items.Sort((a, b) => a.score != b.score ? b.score.CompareTo(a.score) : b.time.CompareTo(a.time));
    if (ranking.items.Count > 5) ranking.items.RemoveRange(5, ranking.items.Count - 5);
    PlayerPrefs.SetString("Ranking", JsonUtility.ToJson(ranking));
    PlayerPrefs.Save();
}

// OnGUI()의 게임 오버 화면
for (int i = 0; i < ranking.items.Count; i++) {
    Record r = ranking.items[i];
    GUI.Label(new Rect(w + 120, h - 60 + i * 30, 300, 30),
        (i + 1) + ". " + r.name + "  " + r.score + "  (" + (int)r.time + "s)");
}
```

닉네임 입력은 OnGUI로 간단히 만들 수 있다. 시작 화면이 있다면 거기에 둔다.
```csharp
playerName = GUI.TextField(new Rect(w - 100, h - 120, 200, 40), playerName, 10);   // 최대 10자
```
이름은 `PlayerPrefs.SetString("LastName", playerName)`으로 저장해 다음 실행 때 기본값으로 쓴다.

**확인할 점**
- 한글 입력은 OnGUI TextField에서 IME 조합이 불안정할 수 있다. uGUI InputField나 TextMeshPro Input Field를 쓰는 편이 안정적이다.
- 방금 등록된 기록이 순위표 몇 번째인지 강조하려면, 추가한 Record 객체의 인덱스를 `IndexOf`로 찾아 색을 바꾼다.

#### B-4. 생존 시간 기록
*제안: 김주헌*

**구현 방향**
- 이미 `stageTime - startTime`으로 계산되는 경과 시간을 결과 화면과 기록에 함께 남긴다. B-3의 Record에 이미 포함되어 있다.
- 최고 생존 시간을 따로 저장하면 "점수는 낮아도 오래 버티기"라는 두 번째 목표가 생긴다.

**구현 방법**
- `SaveRecord()`에 추가한다.
  ```csharp
  float t = stageTime - startTime;
  if (t > PlayerPrefs.GetFloat("BestTime", 0)) PlayerPrefs.SetFloat("BestTime", t);
  ```
- 결과 화면에 "생존 시간 00초 / 최고 00초"를 표시한다.

**확인할 점**
- `Time.time`은 `Time.timeScale`의 영향을 받는다. 따라서 D-3 스테이지 전환이나 J-3 일시정지에서 `timeScale = 0`으로 멈춘 시간은 생존 시간에 포함되지 않는다. 반대로 멈춘 동안 기다리는 연출에는 `WaitForSeconds` 대신 `WaitForSecondsRealtime`을 써야 한다.

### C. 아이템 · 버프

아이템은 모두 0-5의 `CsItem`을 상속하고 `Apply()`만 작성한다. 지속 효과는 0-3의 `RunTimed()`로 처리한다.

**아이템 공통 설계 원칙**
- **모양과 색으로 효과를 알 수 있게 한다.** 김유경안의 테마(시계, 커다란 바구니, 깃털·운동화, 하트)처럼 직관적인 아이콘을 쓴다.
- **효과 중임을 표시한다.** 화면 상단에 아이콘과 남은 시간(초)을 나란히 보여 준다.
- **등장 빈도를 제한한다.** 평균 12초에 1개가 적당하며, 아이템이 계란보다 자주 나오면 계란받기의 긴장이 사라진다.

효과 표시 UI는 한 번 만들어 두고 모든 아이템이 같이 쓴다.
```csharp
// CsManager.OnGUI()
int slot = 0;
foreach (var key in new[] { "slow", "big", "speed", "double", "noBomb", "fever" })
{
    float remain = Remaining(key);
    if (remain <= 0) continue;
    GUI.Label(new Rect(20 + slot * 110, Screen.height - 50, 110, 40),
        "<size='22'>" + key + " " + Mathf.CeilToInt(remain) + "s</size>");
    slot++;
}
```
실제로는 key 대신 아이콘 텍스처(`Dictionary<string, Texture>`)를 그리면 좋다.

#### C-1. 낙하 감속 (시계)
*제안: 김동현 · 최민혁 · 김유경 · 이도경*

**구현 방향**
- 7초간 계란·폭탄·아이템의 낙하 속도를 50%로 줄인다.
- 생성 간격은 그대로 두어, 화면에 떠 있는 낙하물은 오히려 많아진다. 이렇게 하면 "여유"와 "밀도" 사이의 재미가 생긴다.
- (선택) 감속 중 배경음악 `pitch`를 0.8로 낮추고 화면을 약간 푸르게 하면 체감이 커진다.

**구현 방법**
```csharp
// CsItemSlow.cs
public class CsItemSlow : CsItem
{
    protected override void Apply()
    {
        CsManager.inst.RunTimed("slow", duration,
            () => CsManager.slowFactor = 0.5f,
            () => CsManager.slowFactor = 1f);
    }
}
```
- 0-1에서 계란·폭탄이 `FallFactor`를 곱하도록 바꿔 두었으므로 이것으로 끝난다.
- 새(CsBird)와 배경(CsSky)은 느려지지 않으므로 대비가 오히려 잘 드러난다.

**확인할 점**
- 감속이 끝나는 순간 모든 낙하물이 갑자기 빨라진다. 부드럽게 하려면 종료 1초 전부터 `Mathf.Lerp`로 0.5 → 1로 되돌린다.

#### C-2. 바구니 확대
*제안: 문헌민 · 김유경 · 이현수*

**구현 방향**
- 10초간 바구니를 가로 1.5배로 키운다.
- 높이까지 키우면 바구니가 땅에 파묻히거나 떠 보일 수 있으므로 **x, z만** 키운다.
- 커진 만큼 폭탄에도 잘 맞으므로 **장점과 위험이 함께** 커진다는 점을 설계 의도로 삼는다.

**구현 방법**
```csharp
public class CsItemBig : CsItem
{
    protected override void Apply()
    {
        Transform b = CsManager.inst.bucket;
        if (!b) return;
        CsManager.inst.RunTimed("big", duration,
            () => b.localScale = new Vector3(1.5f, 1f, 1.5f),
            () => { if (b) b.localScale = Vector3.one; });
    }
}
```
- 루트의 Scale을 바꾸면 자식 콜라이더(SAFE, Mesh Collider)도 함께 커진다.
- 원래 Scale이 1이 아니면 CsBucket `Start()`에서 `baseScale`을 저장해 두고 곱해서 쓴다.

**확인할 점**
- A-4 피버도 바구니 크기를 바꾼다. 두 효과가 겹칠 때 먼저 끝나는 쪽이 크기를 1로 되돌리는 문제가 생길 수 있다.
  - 해결 1: 크기 배율 변수를 효과별로 따로 둔다. (`bigMul`, `feverMul`)
  - 해결 2: `Update()`에서 `localScale = baseScale × bigMul × feverMul`로 매 프레임 계산한다.
- 확대 중에는 x 이동 범위를 `8.5 - (폭 증가분 / 2)`로 줄여 화면 밖으로 나가지 않게 한다.

#### C-3. 이동 속도 증가 (운동화 · 깃털)
*제안: 문헌민 · 김유경 · 이승민*

**구현 방향**
- 10초간 바구니 이동 속도를 1.5배로 만든다.
- **전제:** 0-6의 속도 기반 이동이 먼저 구현되어 있어야 한다. 순간이동 방식에서는 효과가 없다.

**구현 방법**
```csharp
public class CsItemSpeed : CsItem
{
    protected override void Apply()
    {
        CsManager.inst.RunTimed("speed", duration,
            () => CsBucket.speedMul = 1.5f,
            () => CsBucket.speedMul = 1f);
    }
}
```
- 속도가 올라간 것을 보여 주려면 바구니 뒤에 Trail Renderer를 붙이고 효과 중에만 `emitting = true`로 켠다.

**확인할 점**
- E-2 디버프는 별도 변수 `debuffMul`을 쓰므로 서로 덮어쓰지 않는다. 다만 A-4 피버도 `speedMul`을 쓰므로, 피버와 운동화가 겹칠 때 먼저 끝나는 쪽이 1로 되돌리는 문제는 남는다(C-2와 같은 해결법 적용).

#### C-4. 점수 2배
*제안: 최민혁 · 이도경 · 이승민*

**구현 방향**
- 10초간 계란 점수를 두 배로 한다. 콤보 보너스까지 2배가 되도록 A-1의 `AddScore()`가 `scoreMultiplier`를 마지막에 곱한다.
- 점수 표시 옆에 "×2"를 붙여 적용 중임을 알린다.

**구현 방법**
```csharp
public class CsItemDouble : CsItem
{
    protected override void Apply()
    {
        CsManager.inst.RunTimed("double", duration,
            () => CsManager.scoreMultiplier = 2,
            () => CsManager.scoreMultiplier = 1);
    }
}
```

**확인할 점**
- 피버(A-4)도 `scoreMultiplier = 2`를 쓰므로, 두 효과가 겹치면 먼저 끝나는 쪽이 배율을 1로 되돌린다. 효과별 배율을 곱하는 구조로 바꾸거나, 겹칠 때 ×4를 허용할지 정한다.

#### C-5. 목숨 회복 (하트 · 우유)
*제안: 김민준 · 김유경 · 이현수*

**구현 방향**
- 즉시 효과로, 놓친 계란 수를 1 줄인다(= 목숨 +1). 가득 찬 상태에서 먹으면 점수 보너스로 바꿔 준다.
- 너무 자주 나오면 게임이 끝나지 않으므로 다른 아이템보다 가중치를 낮게 한다. 예를 들어 다른 아이템 10일 때 하트는 4.

**구현 방법**
```csharp
public class CsItemHeart : CsItem
{
    protected override void Apply()
    {
        if (CsManager.miss > 0) CsManager.miss--;
        else CsManager.score += 10;              // 가득 찼을 때 보상
    }
}
```
- 하트 표시(E-1)가 있으면 회복되는 하트 칸을 반짝이게 한다.

#### C-6. 폭탄 일시 차단
*제안: 최민혁*

**구현 방향**
- 6초간 폭탄이 새로 생성되지 않는다.
- 이미 떨어지고 있는 폭탄은 두 가지 중 하나로 처리한다.
  - **① 그대로 둔다:** 구현이 쉽고 긴장이 약간 남는다.
  - **② 모두 터뜨린다:** 시각적으로 시원하고 "구원" 아이템 느낌이 난다.
- 화면에 방패 아이콘을 표시한다.

**구현 방법**
```csharp
// CsManager
static public bool bombBlocked = false;        // InitStage()에서 false

// MakeBomb() 맨 앞
if (bombBlocked) return;
```
```csharp
public class CsItemNoBomb : CsItem
{
    protected override void Apply()
    {
        CsManager.inst.RunTimed("noBomb", duration,
            () => CsManager.bombBlocked = true,
            () => CsManager.bombBlocked = false);

        // ② 떨어지고 있는 폭탄 모두 제거
        foreach (CsBomb b in FindObjectsByType<CsBomb>(FindObjectsSortMode.None))
            b.Explode();
    }
}
```
CsBomb에는 작은 폭발 후 사라지는 public 함수를 추가한다.
```csharp
public void Explode()
{
    Instantiate(expSmall, transform.position, Quaternion.identity);
    Destroy(gameObject);
}
```
`FindObjectsByType`는 Unity 2022.2 이상에서 쓸 수 있다. 이전 버전은 `FindObjectsOfType<CsBomb>()`를 쓴다.

**확인할 점**
- `MakeBomb()`에서 `return`하는 동안 `bombDelay`가 줄지 않으므로, 차단이 풀리자마자 폭탄이 나오지는 않는다. 풀리는 즉시 폭탄이 쏟아지는 것을 막는 효과가 있다.

#### C-7. 저장 후 사용형 아이템
*제안: 최민혁*

**구현 방향**
- 아이템을 먹으면 바로 발동하지 않고 **슬롯 1칸**에 보관한다. 원하는 순간 키를 눌러 사용한다. (PC는 E 또는 마우스 오른쪽, 모바일은 화면의 버튼)
- **슬롯이 차 있을 때 규칙** (하나를 고른다)
  - **새 아이템으로 교체:** 선택의 재미가 생긴다.
  - **새 아이템 즉시 발동:** 손실이 없다.
- 즉시 발동형(하트)과 보관형(시계, 방패)을 나누면 "언제 쓸까"라는 전략이 생긴다.

**구현 방법**
1. `CsItem`에 보관 여부와 아이콘을 추가하고, `Apply()`를 외부에서 호출할 수 있게 `public`으로 한 단계 감싼다.
   ```csharp
   public bool storable = true;
   public Texture icon;
   public void Use() { Apply(); }

   // OnCollisionEnter()의 Apply(); 부분을 교체
   if (storable) CsManager.inst.StoreItem(this);
   else Apply();
   ```
2. 슬롯에 보관하려면 아이템 오브젝트가 사라지면 안 되므로, 오브젝트를 제거하지 않고 **숨긴다**.
   ```csharp
   // CsManager
   CsItem stored;

   public void StoreItem(CsItem item)
   {
       if (stored) Destroy(stored.gameObject);             // 교체 규칙
       stored = item;
       item.gameObject.SetActive(false);
   }

   // Update()
   if (stored && (Input.GetKeyDown(KeyCode.E) || Input.GetMouseButtonDown(1))) {
       stored.Use();
       Destroy(stored.gameObject);
       stored = null;
   }
   ```
3. `CsItem.OnCollisionEnter()`의 `Destroy(gameObject)`는 보관한 경우 실행되지 않도록 분기한다.
4. `OnGUI()`에서 화면 우하단에 슬롯 테두리와 `stored.icon`을 그린다.

**확인할 점**
- 비활성화된 오브젝트에서도 `RunTimed()`는 CsManager에서 실행되므로 코루틴이 멈추지 않는다. 아이템 오브젝트 쪽에서 `StartCoroutine`을 쓰면 비활성화 순간 멈추니 주의한다.

### D. 난이도 · 진행 구조

기존 코드는 **생성 간격**만 줄이는 방식으로 난이도를 올린다. 계란은 2.5초에서 0.5초로 약 100초, 폭탄은 5초에서 0.9초로 약 410초에 걸쳐 줄어든다. 새 난이도 요소는 이 곡선과 **겹친다**는 점을 항상 고려한다.

#### D-1. 점진적 낙하 가속
*제안: 강보민 · 김주헌 · 유상현(구현)*

**구현 방향**
- 시간에 따라 낙하 속도 배율 `levelFactor`를 1.0에서 1.8까지 서서히 올린다.
- 강보민안처럼 초반은 완만하게 만든다. 처음 30초는 가속 없이 적응 시간을 준다.
- 기준을 "시간"과 "받은 개수" 중 무엇으로 할지 정한다.
  - **시간 기준:** 모든 플레이어가 같은 속도로 어려워진다.
  - **받은 개수 기준:** 잘하는 플레이어만 빨리 어려워진다.

**구현 방법**
```csharp
// CsManager.Update()의 if (!isDead) 블록 안 (시간 기준)
float t = stageTime - startTime;
levelFactor = 1f + Mathf.Clamp01((t - 30f) / 150f) * 0.8f;   // 30초 이후 150초 동안 1.0 → 1.8

// 받은 개수 기준으로 하려면
// levelFactor = 1f + Mathf.Min(hit, 100) * 0.008f;           // 100개에서 1.8
```

**확인할 점**
- 계란 생성 간격이 약 100초에 최소가 되고, 그 무렵 낙하 속도도 올라가기 시작한다. 1~3분 구간을 직접 플레이해 보고 난이도가 급격히 뛰는 지점이 없는지 확인한다.
- 속도 기반 이동(0-6)을 쓰는 경우, 낙하가 빨라질수록 바구니가 따라잡지 못하는 거리가 생긴다. 바구니 속도도 조금씩 올리는 방안을 검토한다.

#### D-2. 점수 구간별 단계 상승
*제안: 김주헌*

**구현 방향**
- 연속적인 가속(D-1) 대신 점수 구간마다 **계단식**으로 한 단계씩 올린다.
- 김주헌 구현 방식은 `1 + floor(점수/1000) × 0.2`다.
- 단계가 오르는 순간을 "LEVEL UP!" 문구와 효과음으로 알린다. 무엇이 바뀌었는지 체감시키기 위해서다.

**구현 방법**
```csharp
// CsManager
int level = 0;                          // InitStage()에서 0

// Update()의 if (!isDead) 블록 안
int newLevel = score / 500;             // 정수 나눗셈 → 500점마다 1 증가
if (newLevel != level) {
    level = newLevel;
    levelFactor = 1f + Mathf.Min(level, 8) * 0.1f;        // 최대 1.8배
    ShowPopup("LEVEL " + (level + 1), Vector3.zero);       // J-4
}
```

**확인할 점**
- A-1 콤보나 C-4 점수 2배로 점수가 빨리 오르면 난이도도 빨리 오른다. 잘할수록 어려워지는 구조가 의도에 맞는지 판단한다.
- 폭탄은 따로 올리고 싶다면(김주헌안: 500점마다 폭탄, 1,000점마다 계란) 배율 변수를 `eggLevelFactor`와 `bombLevelFactor`로 나눈다.

#### D-3. 스테이지 전환
*제안: 이현수 · 강미정*

**구현 방향**
- 목표 점수에 도달하면 다음 스테이지로 넘어간다. 스테이지마다 다음이 바뀐다.
  - 속도와 생성 간격
  - 폭탄 비율
  - 배경 색(또는 J-2의 시간대)
  - 배경음악
- 전환할 때 1.5초간 게임을 멈추고 "STAGE 2" 문구를 보여 준다. 쉬는 호흡과 성취감을 준다.
- 스테이지 설정은 코드가 아니라 **인스펙터의 표**로 관리해, 수치를 바꿔 가며 테스트하기 쉽게 한다.

**구현 방법**
```csharp
[System.Serializable]
public class StageData
{
    public int targetScore;             // 이 점수에 도달하면 다음 스테이지
    public float eggDelayMin = 0.5f;    // 계란 최소 생성 간격
    public float bombDelayMin = 0.9f;   // 폭탄 최소 생성 간격
    public float fallFactor = 1f;       // 낙하 속도 배율
    public Color skyColor = Color.white;
    public AudioClip bgm;
}

// CsManager
public StageData[] stages;              // 인스펙터에서 3~5개 입력
int stage = 0;                          // InitStage()에서 0, ApplyStage(0)

void ApplyStage(int i)
{
    StageData s = stages[i];
    levelFactor = s.fallFactor;
    sky.GetComponent<Renderer>().material.color = s.skyColor;   // public Transform sky;
    if (s.bgm) { var a = Camera.main.GetComponent<AudioSource>(); a.clip = s.bgm; a.Play(); }
}

// Update()의 if (!isDead) 블록 안
if (stage < stages.Length - 1 && score >= stages[stage].targetScore)
    StartCoroutine(NextStage());

IEnumerator NextStage()
{
    stage++;
    ApplyStage(stage);
    stageBanner = "STAGE " + (stage + 1);     // OnGUI에서 크게 표시
    Time.timeScale = 0f;
    yield return new WaitForSecondsRealtime(1.5f);
    Time.timeScale = 1f;
    stageBanner = "";
}
```
`MakeEgg()`와 `MakeBomb()`의 `Mathf.Clamp` 최소값을 `stages[stage].eggDelayMin`과 `bombDelayMin`으로 바꾼다.

**확인할 점**
- `NextStage()` 코루틴이 도는 동안 조건이 계속 참이면 중복 실행된다. 위 코드는 `stage++`를 코루틴 첫 줄에서 하므로 다음 프레임에는 조건이 거짓이 된다.
- `Time.timeScale = 0` 동안 `WaitForSeconds`는 멈춘다. 따라서 C 아이템 효과 시간도 함께 멈추는데, 이것이 오히려 공정하다.
- 재시작 시 `Time.timeScale`이 0으로 남아 있지 않도록 `InitStage()`에서 `Time.timeScale = 1f;`를 넣는다.

#### D-4. 모드 · 페이즈 전환
*제안: 유상현(구현)*

**구현 방향**
- 계란 위주 구간(22초)과 폭탄이 쏟아지는 위험 구간(10초)이 번갈아 온다. 유상현 구현 수치를 그대로 쓴다.
- 단조로운 반복을 깨고 "버티는 구간"과 "쓸어 담는 구간"의 리듬을 만든다.
- 위험 구간 **2초 전에 경고**를 한다. "DANGER!" 깜빡임과 경고음을 준다.
- 위험 구간에는 계란 대신 폭탄만 떨어지고 생성 간격이 0.8배가 된다. 폭탄을 잘 피하면 점수를 준다(유상현안 +35점).

**구현 방법**
```csharp
// CsManager
enum Phase { Egg, Danger }
Phase phase = Phase.Egg;
float phaseTimer = 22f;                 // InitStage()에서 phase = Phase.Egg; phaseTimer = 22f;

// Update()의 if (!isDead) 블록 안, MakeEgg()/MakeBomb() 호출부 교체
phaseTimer -= Time.deltaTime;
if (phaseTimer <= 0) {
    phase = (phase == Phase.Egg) ? Phase.Danger : Phase.Egg;
    phaseTimer = (phase == Phase.Egg) ? 22f : 10f;
}
bool warning = (phase == Phase.Egg && phaseTimer < 2f);   // OnGUI에서 DANGER 깜빡임

if (phase == Phase.Egg) { MakeEgg(); MakeBomb(); }
else                    { MakeBomb(); MakeBomb(); }        // 폭탄 생성 타이머를 두 배 속도로 소모
```
폭탄을 피했을 때 점수를 주려면, CsBomb의 GROUND 충돌에서 `if (위험 구간) CsManager.score += 35;`를 넣는다. 이를 위해 `phase`를 static으로 공개한다.

**확인할 점**
- 위험 구간이 끝나는 순간 폭탄이 아직 공중에 많이 남아 있다. 계란 구간 첫 2초는 계란 생성을 쉬게 해 주면 억울한 게임 오버가 줄어든다.
- 모드 남은 시간을 화면에 표시한다. 유상현 구현처럼 HUD에 타이머를 둔다.

#### D-5. 받을 수 있는 위치에만 생성
*제안: 유상현(구현)*

**구현 방향**
- 다음 계란의 x 위치를, 직전 계란 위치에서 **바구니가 제시간에 도달할 수 있는 거리** 안에서 고른다. 운 나쁜 배치로 놓치는 일이 없어지고 실력이 결과를 좌우하게 된다.
- **도달 가능 거리** = 바구니 속도 × (다음 계란이 바닥까지 떨어지는 시간 − 여유 시간)
- 유상현 구현처럼 일정 확률(20%)로 **대시(F-2)를 써야만** 닿는 거리에 배치하면 대시가 필수 기술이 된다.
- **전제:** 0-6 속도 기반 이동이 필요하다. 순간이동 방식에서는 어디든 도달할 수 있어 의미가 없다.

**구현 방법**
```csharp
// CsManager
static public float lastEggX = 0f;      // InitStage()에서 0

// CsEgg.SetPosition()에서 x 계산을 교체
float fallTime = (y - 0.5f) / (speed * CsManager.FallFactor);     // 바구니 높이까지 걸리는 시간
float reach = CsBucket.MaxSpeed * Mathf.Max(0, fallTime - 0.3f);  // 0.3초 반응 여유
float x = Mathf.Clamp(CsManager.lastEggX + Random.Range(-reach, reach), -8.5f, 8.5f);
CsManager.lastEggX = x;
```
`CsBucket.MaxSpeed`는 0-6에서 만든 static 속성으로, 버프·디버프가 반영된 현재 최대 속도다. 대시를 강제할 계란은 `reach`에 대시 이동 거리를 더한 범위의 **바깥쪽 끝**에서 고른다.

**확인할 점**
- 계란이 여러 개 동시에 떨어지므로 "직전 계란 기준"은 근사일 뿐이다. 생성 간격이 0.5초까지 짧아지는 후반에는 모두 받기 어려운데, 그것은 의도된 난이도로 둔다.
- 폭탄에는 적용하지 않는다. 폭탄은 오히려 계란 근처에 떨어져야 위협이 된다.

### E. 생명 · 피해 규칙

#### E-1. 하트 체력 표시
*제안: 김주헌 · 김유경 · 유상현(구현)*

**구현 방향**
- "5개 놓치면 끝"이라는 규칙을 숫자 대신 하트 아이콘으로 보여 준다.
- 시작 하트 수는 `maxLife`로 조절한다. 학생안은 3~6개다.
- 규칙 자체는 그대로 두고, 표시와 판정 값만 변수로 바꾼다.

**구현 방법**
1. CsEgg GROUND 처리의 `if (CsManager.miss >= 5)`를 `if (CsManager.miss >= CsManager.maxLife)`로 바꾼다.
2. Resources 폴더에 `heart_full`, `heart_empty` 이미지를 넣고 `Start()`에서 한 번 불러 둔다.
   ```csharp
   Texture heartFull, heartEmpty;       // Start()에서 Resources.Load

   // OnGUI() — 우상단의 깨진 계란 표시를 교체
   for (int i = 0; i < maxLife; i++) {
       Texture tex = (i < maxLife - miss) ? heartFull : heartEmpty;
       GUI.DrawTexture(new Rect(Screen.width - 50 - i * 42, 20, 36, 32), tex);
   }
   ```
3. 하트를 잃는 순간 해당 칸이 흔들리거나 빨갛게 깜빡이면 피드백이 강해진다.

**확인할 점**
- 하트가 많아지면 화면 중앙의 Time 표시와 겹칠 수 있으니 위치를 조정한다.

#### E-2. 폭탄 = 감속 디버프
*제안: 김주헌*

**구현 방향**
- 폭탄에 맞으면 즉시 게임 오버되는 대신 2초간 바구니 이동 속도가 50%로 떨어진다.
- 폭탄이 무서움을 잃지 않도록 **추가 규칙을 하나** 둔다. 둘 중 하나를 고른다.
  - 폭탄 3회 피격 시 게임 오버
  - 피격 시 하트 1개 감소
- 감속 중에는 바구니를 회색으로 바꾸고 연기 파티클을 붙여 상태를 보여 준다.
- **전제:** 0-6 속도 기반 이동이 필요하다.

**구현 방법**
0-6에서 CsBucket에 버프(`speedMul`)와 분리된 디버프 배율 `debuffMul`을 이미 만들어 두었다.

```csharp
// CsBomb — BUCKET/SAFE 충돌 처리 교체
Instantiate(expBig, transform.position, Quaternion.identity);
AudioSource.PlayClipAtPoint(sndBomb, transform.position);
CsManager.miss++;                                   // 하트 1개 감소 규칙
if (CsManager.miss >= CsManager.maxLife) CsManager.GameOver();
else CsManager.inst.RunTimed("debuff", 2f,
        () => CsBucket.debuffMul = 0.5f,
        () => CsBucket.debuffMul = 1f);
Destroy(gameObject);
```
바구니를 제거하지 않도록 기존의 `Destroy(coll.transform.root.gameObject)`는 지운다.

**확인할 점**
- 폭탄 피격 직후 또 폭탄에 맞으면 연속으로 하트를 잃는다. 피격 후 1초 무적(깜빡임)을 두면 억울함이 줄어든다.

#### E-3. 스턴 폭탄
*제안: 이승민*

**구현 방향**
- 일반 폭탄과 **색이 다른**(예: 파란) 폭탄을 추가한다. 맞으면 게임 오버 대신 1.5초간 조작할 수 없다.
- 스턴 중에는 바구니 위에 별 파티클을 띄우고, 바구니를 좌우로 떨리게 한다.
- 스턴 동안 계란은 계속 떨어지므로 놓치는 것이 실질적인 벌칙이 된다.

**구현 방법**
1. 폭탄 프리팹의 베리언트 `BombStun`을 만들어 머티리얼을 파랗게 한다. CsBomb에 종류 변수를 추가한다.
   ```csharp
   public bool isStun = false;          // BombStun 베리언트에서 true
   ```
2. CsBomb BUCKET/SAFE 충돌 처리 맨 앞에 스턴 분기를 넣는다.
   ```csharp
   if (isStun) {
       Instantiate(expSmall, transform.position, Quaternion.identity);
       CsManager.inst.RunTimed("stun", 1.5f,
           () => CsBucket.isStunned = true,
           () => CsBucket.isStunned = false);
       Destroy(gameObject);
       return;
   }
   ```
3. 0-6의 CsBucket `Update()`에는 이미 `isStunned` 검사가 들어 있다.
4. 폭탄도 가중치 생성표(0-4)로 바꿔 일반:스턴 = 7:3으로 섞는다.

**확인할 점**
- 스턴 폭탄이 계란과 부딪힐 때의 처리를 정한다. 일반 폭탄처럼 계란을 깨도록 기존 GROUND/EGG 처리를 그대로 둬도 된다.

#### E-4. 점수 감점
*제안: 유상현(구현)*

**구현 방향**
- 폭탄 피격 시 점수 −250점. 유상현 구현은 목숨 −1과 함께 적용한다.
- **처벌이 이중**(목숨+점수)이면 과할 수 있다. 다음 두 방식을 비교해 하나를 고른다.
  - 목숨은 두고 감점만: 점수 경쟁형
  - 목숨만 깎고 감점 없음: 생존형
- 점수가 음수가 되지 않게 한다.

**구현 방법**
```csharp
// CsBomb BUCKET/SAFE 처리
CsManager.score = Mathf.Max(0, CsManager.score - 250);
CsManager.inst.ShowPopup("-250", transform.position);     // J-4, 빨간 글씨
CsManager.BreakCombo();                                    // 콤보도 끊기
```

**확인할 점**
- 감점 폭은 계란 점수 체계에 맞춘다. 유상현 구현은 계란 1개가 100점 이상이라 −250이 계란 2~3개 분량이다. 기존 1점 체계라면 −3 정도가 비슷한 무게다.

### F. 조작 확장

#### F-1. 키보드 좌우 이동
*제안: 김주헌 · 김유경 · 이건희*

**구현 방향**
- A/D 또는 ←/→ 키로 바구니를 움직인다. 마우스·터치 조작도 함께 살려 두어 PC·모바일 모두 지원한다.
- 키보드는 순간이동이 없으므로 **이동 속도가 곧 난이도**가 된다.
  - 화면 폭은 17유닛이다.
  - 속도 12면 끝에서 끝까지 약 1.4초 걸린다.
  - 계란 낙하 시간은 2.4~4.7초다.
- 입력이 들어온 쪽이 우선한다. 키를 누르면 마우스 목표를 무시하고, 마우스를 누르면 키보드 입력을 덮어쓴다.

**구현 방법**
0-6의 CsBucket `Update()`를 확장한다.
```csharp
float h = Input.GetAxisRaw("Horizontal");               // A/D, ←/→ : -1, 0, 1
float x = transform.position.x;

if (h != 0) {
    x += h * MaxSpeed * Time.deltaTime;                 // 키보드: 방향 × 속도
    targetX = x;                                        // 마우스 목표를 현재 위치로 맞춰 충돌 방지
}
else if (Input.GetButton("Fire1")) {
    Vector3 mousePos = Input.mousePosition; mousePos.z = 24;
    targetX = Camera.main.ScreenToWorldPoint(mousePos).x;
}
x = Mathf.MoveTowards(x, targetX, MaxSpeed * Time.deltaTime);
transform.position = new Vector3(Mathf.Clamp(x, -8.5f, 8.5f), 0, -2);
```
- `GetAxisRaw`는 즉시 -1/0/1을 돌려준다.
- `GetAxis`는 Input Manager의 Gravity·Sensitivity 설정에 따라 서서히 변해 약간의 관성이 생긴다. 둘을 바꿔 가며 조작감을 비교해 보자.

**확인할 점**
- New Input System만 활성화된 프로젝트(Unity 6 기본 설정)에서는 `Input.GetAxis`가 오류를 낸다. Project Settings → Player → Active Input Handling을 **Both**로 바꾸거나, `InputAction`으로 작성한다. 이건희 계획서에도 이 설정이 언급되어 있다.

#### F-2. 대시
*제안: 유상현(구현)*

**구현 방향**
- Shift를 누르면 짧은 시간 매우 빠르게 이동한다. 유상현 구현 수치를 참고한다.
  - 대시 속도 27 (기본 9.5의 약 2.8배)
  - 지속 최대 0.48초
  - 쿨다운 0.7초
- 대시 방향은 누르고 있는 방향키, 없으면 마지막 이동 방향으로 한다.
- **잔상 효과**로 손맛을 준다. 0.05초마다 바구니 복제본을 남기고 서서히 투명하게 만든다.
- 쿨다운을 화면에 막대로 보여 주면 대시 타이밍을 계산하며 플레이하게 된다.

**구현 방법**
```csharp
// CsBucket
public float dashSpeed = 27f, dashTime = 0.25f, dashCooldown = 0.7f;
public GameObject ghostPrefab;          // 바구니 모양 + 반투명 머티리얼, 스크립트 CsGhost
float dashRemain = 0, cooldownRemain = 0, ghostTimer = 0;
int lastDir = 1;

// Update() — 이동 처리 앞에
if (h != 0) lastDir = (int)Mathf.Sign(h);
cooldownRemain -= Time.deltaTime;
if (Input.GetKeyDown(KeyCode.LeftShift) && cooldownRemain <= 0) {
    dashRemain = dashTime;
    cooldownRemain = dashCooldown;
}

if (dashRemain > 0) {
    dashRemain -= Time.deltaTime;
    x += lastDir * dashSpeed * Time.deltaTime;
    targetX = x;
    ghostTimer -= Time.deltaTime;
    if (ghostTimer <= 0) { Instantiate(ghostPrefab, transform.position, transform.rotation); ghostTimer = 0.05f; }
}
```
```csharp
// CsGhost.cs — 잔상: 0.3초 동안 투명해지며 사라짐
public class CsGhost : MonoBehaviour
{
    float life = 0.3f;
    Material mat;
    void Start() { mat = GetComponentInChildren<Renderer>().material; }
    void Update()
    {
        life -= Time.deltaTime;
        Color c = mat.color; c.a = Mathf.Max(0, life / 0.3f) * 0.5f; mat.color = c;
        if (life <= 0) Destroy(gameObject);
    }
}
```
- 잔상 프리팹은 바구니 모델만 복제하고, 콜라이더와 스크립트는 뺀다. 머티리얼은 투명 셰이더(Legacy Transparent/Diffuse)를 쓴다.
- 모바일에서는 화면을 빠르게 두 번 탭하면 대시하도록 하거나 대시 버튼을 둔다.

**확인할 점**
- 대시 중 폭탄에 맞으면 어떻게 할지 정한다. 무적으로 두면 대시가 회피기가 되고, 아니면 이동기에 그친다.
- 대시 거리 = `dashSpeed × dashTime`이다. D-5에서 "대시로만 닿는 거리"를 계산할 때 이 값을 쓴다.

#### F-3. 미끄러지는 관성 이동
*제안: 김유경*

**구현 방향**
- 키를 떼도 바로 멈추지 않고 미끄러지며 멈춘다. 가속과 감속을 분리하면 "빙판 느낌"부터 "묵직한 느낌"까지 조절할 수 있다.
- 조작감(게임 필) 실험 과제로 좋다. 가속·감속 값을 바꾼 3가지 버전을 만들어 친구에게 블라인드 테스트해 본다.

**구현 방법**
```csharp
// CsBucket
public float accel = 40f;               // 가속도 (클수록 즉시 반응)
public float decel = 15f;               // 감속도 (작을수록 오래 미끄러짐)
float velocity = 0;

// Update() — 키보드 이동 부분 교체
float targetV = h * MaxSpeed;
float rate = (h != 0) ? accel : decel;
velocity = Mathf.MoveTowards(velocity, targetV, rate * Time.deltaTime);
x += velocity * Time.deltaTime;

if (x <= -8.5f || x >= 8.5f) velocity = 0;              // 벽에 닿으면 멈춤
```

**확인할 점**
- 방향을 반대로 바꿀 때도 `accel`이 적용되어 반응이 느려진다. 반대 방향 입력 시에는 `accel × 2`를 쓰는 식으로 조정한다.
- 관성은 계란받기를 **더 어렵게** 만든다. 감속 값을 너무 낮추면 조작 불능처럼 느껴진다.

#### F-4. 점프
*제안: 김유경*

**구현 방향**
- 점프는 공중의 계란을 받는 데는 쓸모가 적다. 바구니 높이가 올라가면 오히려 받기 어렵다. 그래서 **바닥의 위협을 피하는 용도**로 설계한다.
  - I-3 추격하는 닭
  - 굴러오는 장애물
- 점프 중에도 좌우 이동은 가능하게 한다.
- 키는 Space를 쓴다. G-1(헛간 비우기)도 Space를 쓴다면 키를 나눈다.

**구현 방법**
```csharp
// CsBucket
public float jumpPower = 9f, gravity = 25f;
float vy = 0, y = 0;

// Update()
bool grounded = (y <= 0f);
if (grounded && Input.GetKeyDown(KeyCode.Space)) vy = jumpPower;
vy -= gravity * Time.deltaTime;
y = Mathf.Max(0f, y + vy * Time.deltaTime);
if (y <= 0f) vy = 0;

transform.position = new Vector3(Mathf.Clamp(x, -8.5f, 8.5f), y, -2);   // 기존 y = 0 고정을 교체
```
- 최고 높이 = `jumpPower² / (2 × gravity)`로, 위 값이면 약 1.6유닛이다. 체공 시간은 `2 × jumpPower / gravity`로 약 0.7초다.

**확인할 점**
- 바구니 y가 바뀌므로 D-5의 낙하 시간 계산 기준(바구니 높이)이 달라진다.
- Rigidbody를 쓰지 않는 수동 물리이므로, 착지 판정은 y ≤ 0으로 충분하다.

### G. 자원 관리

#### G-1. 바구니 용량 + 헛간 비우기
*제안: 윤성훈*

**구현 방향**
- 바구니에는 계란을 최대 5개만 담을 수 있다. 가득 차면 계란을 받아도 튕겨 나가 떨어진다.
- 화면 왼쪽 끝의 **헛간** 앞에서 Space를 누르면 바구니 계란을 헛간으로 옮긴다. **점수는 헛간에 넣은 계란 수로 계산**한다.
- 이렇게 하면 "계속 받을까, 비우러 갈까"라는 선택이 생긴다. 헛간에 가는 동안 계란을 놓치는 기회비용이 게임의 핵심이 된다.
- **위험 요소 (선택):** 폭탄에 맞으면 바구니 속 계란을 모두 잃는다. 많이 담을수록 위험이 커진다.
- **UI:** 바구니 수 `3/5`와 헛간 수를 따로 표시한다. 가득 차면 "FULL!"을 깜빡이고 헛간 방향 화살표를 띄운다.

**구현 방법**
1. 씬 왼쪽 끝(x = -8 부근)에 헛간 모델 또는 이미지를 배치한다.
2. CsManager에 변수를 추가한다.
   ```csharp
   static public int basketCount = 0;   // 바구니 속 계란 (InitStage()에서 0)
   static public int barnCount = 0;     // 헛간에 넣은 계란 = 점수 기준
   public int capacity = 5;
   public float barnX = -7.5f;          // 이 x보다 왼쪽이면 헛간 앞
   ```
3. CsEgg SAFE 처리를 바꾼다. 가득 찼으면 받지 못한다.
   ```csharp
   case "SAFE":
       if (CsManager.basketCount >= CsManager.inst.capacity) {
           CsManager.inst.ShowPopup("FULL!", transform.position);
           GetComponent<Collider>().enabled = false;        // 바구니를 통과해 바닥으로 떨어짐 → miss 처리
           break;
       }
       CsManager.basketCount++;
       CsManager.hit++;
       ...
   ```
   콜라이더를 끄면 바닥에도 닿지 않는다. 따라서 miss로 셀지는 규칙으로 정해 `Invoke`로 처리하거나, 끄지 말고 옆으로 튕겨 내는 힘(`Rigidbody.AddForce`)을 준다.
4. CsManager `Update()`에서 비우기를 처리한다.
   ```csharp
   if (bucket && bucket.position.x < barnX && basketCount > 0 && Input.GetKeyDown(KeyCode.Space)) {
       barnCount += basketCount;
       score += basketCount * 10 + (basketCount == capacity ? 20 : 0);   // 가득 채워 넣으면 보너스
       basketCount = 0;
   }
   ```
5. 바구니 안에 계란이 쌓여 보이게 하려면, 바구니 자식으로 계란 모델 5개를 미리 배치해 두고 `basketCount`만큼 `SetActive(true)`한다.

**확인할 점**
- 헛간이 한쪽 끝에만 있으면 반대편 계란은 비운 직후에만 받기 쉽다. 헛간을 양쪽에 두거나 위치를 주기적으로 바꾸는 변형도 실험해 본다.
- 모바일에서는 Space 대신 "헛간 앞에 1초 머무르면 자동 비우기"가 자연스럽다.

### H. 수집 · 성장

#### H-1. 특수 달걀 도감
*제안: 강미정*

**구현 방향**
- 희귀 달걀(불, 물, 용암, 별, 옵시디언 등)을 한 번이라도 받으면 도감에 등록된다. 점수와 별개로 **수집 동기**를 준다.
- 도감은 영구 저장되며, 판을 거듭할수록 채워진다.
- **도감 화면**
  - 미획득 달걀은 검은 실루엣과 "???"로 보여 준다.
  - 획득한 달걀은 이름과 설명, 첫 획득일을 보여 준다.
- 새 달걀을 처음 받으면 "NEW!" 알림을 띄운다.

**구현 방법**
1. 달걀 종류마다 A-2처럼 베리언트를 만들고 `eggId`를 고유하게 지정한다. (예: `fire`, `water`, `lava`, `star`, `obsidian`)
2. 도감 정보를 담는 목록을 CsManager에 둔다.
   ```csharp
   [System.Serializable]
   public class DexEntry { public string id; public string title; public Texture icon; [TextArea] public string desc; }
   public DexEntry[] dex;               // 인스펙터에서 입력
   ```
3. CsEgg SAFE 처리에서 등록한다.
   ```csharp
   string key = "Dex_" + eggId;
   if (eggId != "normal" && PlayerPrefs.GetInt(key, 0) == 0) {
       PlayerPrefs.SetInt(key, 1);
       CsManager.inst.ShowPopup("NEW! " + eggId, transform.position);
   }
   ```
4. 도감 화면은 시작 화면(J-3)의 버튼으로 연다. 격자 형태로 아이콘을 그리되, 미획득이면 `GUI.color = Color.black`으로 실루엣을 만든다.
   ```csharp
   for (int i = 0; i < dex.Length; i++) {
       bool owned = PlayerPrefs.GetInt("Dex_" + dex[i].id, 0) == 1;
       GUI.color = owned ? Color.white : Color.black;
       GUI.DrawTexture(new Rect(100 + (i % 5) * 110, 150 + (i / 5) * 130, 90, 90), dex[i].icon);
       GUI.color = Color.white;
       GUI.Label(new Rect(100 + (i % 5) * 110, 245 + (i / 5) * 130, 100, 30), owned ? dex[i].title : "???");
   }
   ```

**확인할 점**
- 희귀도 조절: 가중치 0.5~2 정도면 몇 판에 한 번 나온다. 너무 드물면 존재를 모르고 지나가므로, 도감 화면에서 "힌트"를 주는 것이 좋다.

#### H-2. 조건부 등장 · 조합
*제안: 강미정*

**구현 방향**
- 특정 순서로 달걀을 받으면 숨겨진 달걀이 등장한다. 예를 들어 물 달걀 → 용암 달걀 = 옵시디언 달걀이다.
- 조합 규칙(레시피)은 데이터로 관리해 쉽게 늘릴 수 있게 한다.
- 조합에 성공하면 다음 계란 하나가 **반드시** 결과 달걀로 나오게 한다. 확률에 맡기지 않는다.
- **힌트 제공:** 재료 달걀을 모두 도감에 등록하면 레시피 자리에 "물 + ? = ?"처럼 일부를 공개한다.

**구현 방법**
```csharp
[System.Serializable]
public class Recipe { public string first; public string second; public Transform result; }

// CsManager
public Recipe[] recipes;
static public string lastCaughtId = "";           // InitStage()에서 ""
Transform reserved;                               // 다음에 반드시 나올 계란

public void OnEggCaught(string id)                // CsEgg SAFE 처리에서 호출
{
    foreach (Recipe r in recipes)
        if (r.first == lastCaughtId && r.second == id) {
            reserved = r.result;
            ShowPopup("?! 무언가 일어난다", Vector3.zero);
        }
    if (id != "normal") lastCaughtId = id;        // 일반 계란은 순서를 끊지 않음(규칙에 따라 선택)
}

// MakeEgg()의 Instantiate 부분
Transform prefab = reserved ? reserved : (eggTable.Length > 0 ? Pick(eggTable) : egg);
reserved = null;
Instantiate(prefab);
```

**확인할 점**
- "사이에 일반 계란을 받아도 순서가 유지되는가"를 규칙으로 정해야 한다. 위 코드는 유지하는 쪽이다. 엄격하게 하려면 일반 계란에서도 `lastCaughtId`를 갱신한다.
- 3개 이상 순서가 필요한 레시피는 `Queue<string>`으로 최근 N개를 저장해 비교한다.

#### H-3. 상점 · 스킨
*제안: 최민혁 · 이건희*

**구현 방향**
- 게임 오버 시 점수에 비례해 코인을 지급한다(예: 점수 ÷ 10). 코인으로 바구니·계란·폭탄 스킨을 산다.
- 스킨은 **머티리얼(텍스처) 교체**로 구현해 모델 제작 부담을 줄인다.
- 보유 코인, 구매한 스킨, 착용 중인 스킨을 영구 저장한다.
- 상점은 시작 화면(J-3)에서 들어간다. 게임 도중에는 열지 않는다.

**구현 방법**
```csharp
[System.Serializable]
public class Skin { public string id; public string title; public int price; public Material bucketMat; public Texture preview; }

// CsShop.cs (시작 화면에 배치) — 핵심 함수
public Skin[] skins;

int Coins { get => PlayerPrefs.GetInt("Coins", 0); set => PlayerPrefs.SetInt("Coins", value); }
bool Owned(Skin s) => s.price == 0 || PlayerPrefs.GetInt("Skin_" + s.id, 0) == 1;

void Buy(Skin s)
{
    if (Owned(s) || Coins < s.price) return;
    Coins -= s.price;
    PlayerPrefs.SetInt("Skin_" + s.id, 1);
    PlayerPrefs.Save();
}

void Equip(Skin s) { if (Owned(s)) PlayerPrefs.SetString("SkinEquip", s.id); }
```
- 게임 씬의 CsBucket `Start()`에서 착용 스킨을 찾아 `GetComponentInChildren<Renderer>().material = skin.bucketMat`으로 적용한다.
- 코인 지급은 `SaveRecord()`에서 `PlayerPrefs.SetInt("Coins", PlayerPrefs.GetInt("Coins", 0) + score / 10)`로 한다.

**확인할 점**
- 스킨 목록(Skin 배열)을 게임 씬과 상점 씬이 함께 써야 한다. `ScriptableObject`로 만들어 두 씬에서 같은 에셋을 참조하는 방식을 권장한다.
- 가격은 "평균 점수로 3~5판"이면 살 수 있게 책정한다.

#### H-4. 로그라이크 강화
*제안: 이건희*

**구현 방향**
- 스테이지(D-3)나 방을 클리어할 때마다 강화 3개 중 1개를 고른다. 이번 판에만 적용된다.
  - 예: 바구니 +10% 크기, 이동 속도 +15%, 하트 +1, 점수 +20%, 황금 계란 확률 +50%
- 골드로 사는 **영구 강화**(시작 하트 +1 등)는 H-3 상점 구조를 그대로 활용한다.
- 강화 선택 중에는 게임을 멈춘다(`Time.timeScale = 0`).
- 같은 강화를 여러 번 고를 수 있게 하되, 최대 중첩을 둔다.

**구현 방법**
```csharp
[System.Serializable]
public class Upgrade { public string id; public string title; public string desc; public int maxStack = 3; }

// CsManager
public Upgrade[] upgradePool;
Dictionary<string, int> stacks = new Dictionary<string, int>();   // 이번 판 강화 현황
Upgrade[] choices;                      // 화면에 보여 줄 3개 (null이면 선택 화면 아님)
static public float scoreBonusRate = 0f; // 점수 강화 비율 — AddScore()에서 (1 + scoreBonusRate)를 곱함, InitStage()에서 0

void OfferUpgrades()                    // 스테이지 클리어 시 호출
{
    var pool = new List<Upgrade>();
    foreach (var u in upgradePool)
        if (!stacks.ContainsKey(u.id) || stacks[u.id] < u.maxStack) pool.Add(u);
    choices = new Upgrade[Mathf.Min(3, pool.Count)];
    for (int i = 0; i < choices.Length; i++) {
        int k = Random.Range(0, pool.Count);
        choices[i] = pool[k];
        pool.RemoveAt(k);               // 중복 없이 3개
    }
    Time.timeScale = 0f;
}

void Choose(Upgrade u)                  // OnGUI 버튼에서 호출
{
    stacks[u.id] = stacks.TryGetValue(u.id, out int n) ? n + 1 : 1;
    switch (u.id) {
        case "life":  maxLife++; break;
        case "speed": CsBucket.inst.moveSpeed *= 1.15f; break;
        case "score": scoreBonusRate += 0.2f; break;     // AddScore()에서 곱함
    }
    choices = null;
    Time.timeScale = 1f;
}
```
- `OnGUI()`에서 `choices != null`이면 화면 중앙에 카드 3장을 버튼으로 그린다.

**확인할 점**
- 강화는 이번 판에만 적용되어야 한다. `moveSpeed`처럼 인스턴스 값을 바꾸면 씬을 다시 불러올 때 원래대로 돌아가므로 괜찮다. static 값(`maxLife`)은 `InitStage()`에서 되돌려야 한다.

### I. 적 · 전투

세 기능 모두 게임 구조를 크게 바꾸므로 **별도 씬이나 게임 모드**로 만드는 것을 권장한다. 기존 계란받기 모드는 그대로 두고 시작 화면에서 모드를 고르게 한다.

#### I-1. 계란을 던지는 적과 받아치기
*제안: 이건희(구현 진행 중)*

**구현 방향**
- 화면 위쪽에 닭(적) 2~3마리가 좌우로 움직이며 일정 간격으로 계란을 던진다. 계란이 하늘에서 "생성"되는 것이 아니라 **누군가 던진다**는 점이 핵심 변형이다.
- 바구니로 계란을 받으면 **그 계란을 던진 닭**이 데미지를 입는다. 받는 것이 곧 공격이다.
- 닭은 체력 3, 모든 닭을 처치하면 방 클리어 → 다음 방으로 진행한다.
- 이건희안의 계란 종류(일반·황금·폭탄 계란)를 확률로 섞는다.

**구현 방법**
1. 적 스크립트 `CsEnemy`를 만든다.
   ```csharp
   public class CsEnemy : MonoBehaviour
   {
       public int hp = 3;
       public Transform eggPrefab;
       public float throwDelay = 2.5f, moveRange = 7f, moveSpeed = 1.5f;
       float timer, baseX;

       void Start() { baseX = transform.position.x; timer = Random.Range(0.5f, throwDelay); }

       void Update()
       {
           float x = baseX + Mathf.Sin(Time.time * moveSpeed + baseX) * moveRange * 0.3f;
           transform.position = new Vector3(Mathf.Clamp(x, -moveRange, moveRange), transform.position.y, transform.position.z);

           timer -= Time.deltaTime;
           if (timer <= 0) { Throw(); timer = throwDelay * Random.Range(0.8f, 1.2f); }
       }

       void Throw()     // 애니메이션을 쓴다면 Animation Event에서 호출
       {
           Transform e = Instantiate(eggPrefab, transform.position + Vector3.down, Quaternion.identity);
           e.GetComponent<CsEgg>().owner = this;
       }

       public void TakeDamage(int dmg)
       {
           hp -= dmg;
           if (hp <= 0) { CsRoom.inst.OnEnemyDead(this); Destroy(gameObject); }
       }
   }
   ```
2. CsEgg에 `public CsEnemy owner;`를 추가한다. SAFE 처리에서 `if (owner) owner.TakeDamage(1);`를 호출한다. 던진 계란은 `SetPosition()`의 무작위 위치 지정을 건너뛰도록 맨 앞에 `if (owner) { speed = 4f; return; }` 분기를 넣는다. `Instantiate()` 직후 대입한 owner는 새 오브젝트의 `Start()`보다 먼저 설정되므로 이 분기가 정상 동작한다.
3. 방 관리 `CsRoom`: 방마다 적 배치 정보를 두고, 적이 모두 사라지면 클리어 연출 후 다음 방의 적을 생성한다.
4. 던지는 궤적을 포물선으로 하려면 계란 Rigidbody에 `velocity`를 주고 Use Gravity를 켠다. 이 경우 Update의 Translate는 쓰지 않는다.

**확인할 점**
- 던진 주체가 먼저 죽으면 공중의 계란의 `owner`는 파괴된 객체가 된다. Unity에서는 파괴된 객체를 `if (owner)`로 검사하면 false가 되므로 안전하다.
- 모든 계란이 적에게 데미지를 주면 전투가 너무 쉬워진다. 받아야 할 계란과 피해야 할 계란(폭탄 계란)을 섞는다.

#### I-2. 몬스터 · 보스와 탄환
*제안: 최민혁*

**구현 방향**
- 일정 점수나 스테이지 도달 시 보스가 등장한다. 보스 체력 막대가 화면 상단에 표시된다.
- 계란을 받을 때마다 보스 체력이 감소한다. 황금 계란은 더 큰 데미지다. 체력이 0이 되면 **클리어**, 처음으로 "승리 조건"이 생긴다.
- 보스는 탄환을 쏜다. 바구니에 맞으면 하트 −1이다(E-1).
- **탄환 패턴**
  - 조준탄: 바구니 현재 위치로 발사
  - 부채꼴 확산탄
  - 체력 50% 이하에서 발사 간격 단축

**구현 방법**
```csharp
public class CsBoss : MonoBehaviour
{
    static public CsBoss inst;
    public int maxHp = 30;
    public int hp;
    public Transform bulletPrefab;
    float fireTimer = 2f;

    void Awake() { inst = this; hp = maxHp; }

    void Update()
    {
        fireTimer -= Time.deltaTime;
        if (fireTimer <= 0) {
            if (hp > maxHp / 2) FireAimed();
            else FireSpread(5, 60f);
            fireTimer = (hp > maxHp / 2) ? 2f : 1.2f;
        }
    }

    void FireAimed()
    {
        Vector3 dir = (CsBucket.inst.transform.position - transform.position).normalized;
        Instantiate(bulletPrefab, transform.position, Quaternion.identity).GetComponent<CsBullet>().dir = dir;
    }

    void FireSpread(int count, float angle)
    {
        for (int i = 0; i < count; i++) {
            float a = -angle / 2 + angle * i / (count - 1);
            Vector3 dir = Quaternion.Euler(0, 0, a) * Vector3.down;
            Instantiate(bulletPrefab, transform.position, Quaternion.identity).GetComponent<CsBullet>().dir = dir;
        }
    }

    public void TakeDamage(int dmg)
    {
        hp -= dmg;
        if (hp <= 0) CsManager.inst.StageClear();    // 승리 처리 함수 (결과 화면 전환 등, 직접 작성)
    }
}
```
- `CsBullet`은 `dir × speed`로 이동하고, BUCKET/SAFE에 닿으면 하트를 감소시킨 뒤 사라진다. GROUND에 닿아도 사라진다. 태그는 **BULLET**으로 한다.
- CsEgg SAFE 처리에서 `if (CsBoss.inst) CsBoss.inst.TakeDamage(point);`를 호출한다.
- 보스 체력 막대는 `OnGUI()`에서 `GUI.DrawTexture`로 빨간 막대의 폭을 `hp / maxHp` 비율로 그린다.

**확인할 점**
- 탄환과 계란이 같은 z 평면이면 서로 부딪힌다. 0-5의 레이어 설정으로 충돌하지 않게 한다.
- 보스를 처치한 뒤의 흐름을 정한다. 결과 화면으로 갈지, 다음 스테이지로 갈지, 무한 모드로 이어 갈지 결정한다.

#### I-3. 추격하는 화난 닭
*제안: 김유경*

**구현 방향**
- 일정 시간(또는 스테이지)마다 화난 닭이 화면 한쪽에서 **땅 위로** 달려와 바구니를 쫓는다. 닿으면 하트 −1과 넉백이다.
- 닭은 8초 후 반대편으로 사라진다. 등장 1초 전에 화면 가장자리에 "!" 경고를 띄운다.
- **피하는 수단:** 대시(F-2)로 닭을 지나치거나, 점프(F-4)로 넘는다. 두 기능을 쓸 이유를 만들어 주는 적이다.

**구현 방법**
```csharp
public class CsAngryChicken : MonoBehaviour
{
    public float speed = 5f, lifeTime = 8f;
    float hitCooldown = 0;

    void Update()
    {
        lifeTime -= Time.deltaTime;
        if (!CsBucket.inst) return;
        float targetX = (lifeTime > 0) ? CsBucket.inst.transform.position.x : 20f;    // 시간이 다 되면 퇴장
        Vector3 p = transform.position;
        p.x = Mathf.MoveTowards(p.x, targetX, speed * Time.deltaTime);
        transform.position = p;
        transform.localScale = new Vector3(targetX < p.x ? -1 : 1, 1, 1);             // 진행 방향으로 뒤집기
        if (lifeTime < -3f) Destroy(gameObject);

        hitCooldown -= Time.deltaTime;
        Vector3 b = CsBucket.inst.transform.position;
        if (hitCooldown <= 0 && Mathf.Abs(b.x - p.x) < 1f && b.y < 0.8f) {       // 가까이 있고 점프 중이 아닐 때
            hitCooldown = 1.5f;
            CsManager.miss++;
            if (CsManager.miss >= CsManager.maxLife) CsManager.GameOver();
        }
    }
}
```
- 충돌을 콜라이더 대신 거리로 판정하면 점프 높이(`b.y`) 조건을 넣기 쉽다.
- 닭의 속도는 바구니 기본 속도보다 **느리게** 한다(바구니 12, 닭 5). 걷기만으로도 도망칠 수는 있지만 계란을 받으러 가기 어려워진다. 이것이 압박의 핵심이다.

**확인할 점**
- 닭의 스프라이트 애니메이션은 CsBird와 같은 방식(텍스처 오프셋)으로 만들 수 있다. CsBird를 복사해 수평 이동만 바꿔 재활용하면 된다.

### J. 연출 · 환경 · UI

#### J-1. 테마 교체
*제안: 유상현(구현)*

**구현 방향**
- 계란 대신 과일·음식(사과, 배, 수박 조각 등)이 떨어지게 해 분위기를 바꾼다. 스크립트는 그대로 두고 **외형만** 바꾼다.
- 여러 종류를 무작위로 섞으면 A-2·A-3의 등급과 결합할 수 있다. 예를 들어 사과 1점, 수박 3점이다.
- 테마에 맞게 함께 교체할 것들이 있다.
  - 깨진 이미지
  - 점수 아이콘
  - 효과음
  - 배경

**구현 방법**
1. 과일 모델이나 이미지를 준비해 A-2처럼 계란 프리팹의 베리언트로 만든다. 3D 모델이면 Mesh Filter를 교체하고, 이미지면 Quad에 텍스처를 입힌다.
2. 한 프리팹 안에서 텍스처만 무작위로 바꾸는 간단한 방법도 있다.
   ```csharp
   // CsEgg
   public Texture[] looks;              // 비어 있으면 원래 모양
   void Start()
   {
       if (looks.Length > 0)
           GetComponent<Renderer>().material.mainTexture = looks[Random.Range(0, looks.Length)];
       SetPosition();
   }
   ```
3. EggBroken의 깨진 이미지를 `public Texture brokenTexture`로 바꿔 테마별로 지정한다. "과즙이 튄 이미지" 등을 쓴다.
4. 모양이 크게 다르면 콜라이더를 모델에 맞게 조정한다. 길쭉한 바나나에는 Capsule Collider가 맞다.

**확인할 점**
- 계란의 z축 기울기(−30~30°)는 과일에서도 자연스러운지 확인한다.

#### J-2. 날씨 · 시간 변화
*제안: 최민혁*

**구현 방향**
- 게임이 진행되면서 낮 → 노을 → 밤 → 새벽으로 하늘과 조명이 서서히 바뀐다. 한 주기는 2분이다.
- 밤에는 화면이 어두워져 계란이 잘 보이지 않는 **난이도 요소**가 될 수도 있다. 계란에 약한 발광을 주어 보완한다.
- 날씨(비·눈)는 무작위로 30초간 발생하며, 파티클로 표현한다.
  - 연출만 할 수 있다.
  - 게임에 영향을 줄 수도 있다. (비: 바구니가 미끄러짐 = F-3 감속값 감소)

**구현 방법**
```csharp
// CsDayCycle.cs (GameManager 또는 별도 오브젝트에 부착)
public Light sun;                       // Directional Light
public Renderer sky;                    // Sky 오브젝트
public Gradient skyColor;               // 인스펙터에서 낮-노을-밤-새벽 색 지정
public Gradient lightColor;
public float dayLength = 120f;          // 한 주기(초)
public ParticleSystem rain;

void Update()
{
    float t = (Time.time % dayLength) / dayLength;          // 0~1 반복
    sky.material.color = skyColor.Evaluate(t);
    sun.color = lightColor.Evaluate(t);
    sun.intensity = Mathf.Lerp(0.3f, 1.1f, Mathf.Sin(t * Mathf.PI));   // 밤에 어둡게
    sun.transform.rotation = Quaternion.Euler(t * 360f - 90f, 30f, 0);
}
```
- `Gradient`는 인스펙터에서 색 막대를 직접 편집할 수 있어 수치 조정이 편하다.
- Sky 텍스처는 CsSky가 오프셋 스크롤을 계속하므로 색만 곱해진다. 머티리얼 셰이더가 `_Color`를 지원하는지 확인한다(Legacy Diffuse 계열은 지원).
- 비는 `rain.Play()`/`Stop()`을 코루틴으로 무작위 호출한다.

**확인할 점**
- D-3 스테이지와 연결하면 "스테이지 1 낮, 2 노을, 3 밤"처럼 시간대가 난이도 표시 역할을 한다.
- 밤에는 UI 글자색(남색 등)이 잘 안 보일 수 있으니 테두리나 그림자를 넣는다.

#### J-3. 타이틀 · 결과 화면
*제안: 김주헌 · 이건희*

**구현 방향**
- 게임 상태를 **Title → Playing → GameOver** 세 가지로 나눈다.
  - Title: 게임 이름, 시작, 도감·상점(H-1, H-3), 종료 버튼
  - GameOver: 점수, 최고 기록, 순위표(B-3), 다시하기, 타이틀로 버튼
- 구현 방식은 두 가지 중 고른다.
  - **한 씬에서 상태 전환:** 구조가 단순하고 기존 코드 수정이 적다.
  - **씬 분리 (TitleScene / GameScene):** 역할이 분명하고 확장에 유리하다. Build Settings에 두 씬을 모두 등록한다.
- 이 기회에 OnGUI 대신 **uGUI(Canvas)** 로 전환하는 것을 권장한다. 해상도 대응, 버튼 디자인, 한글 입력(B-3)이 쉬워진다.

**구현 방법 (한 씬 + 상태 전환)**
```csharp
// CsManager
public enum GameState { Title, Playing, GameOver }
static public GameState state = GameState.Title;

void Start()
{
    ...
    state = GameState.Title;
    Time.timeScale = 0f;                // 타이틀에서는 멈춰 둠
}

void StartGame()                        // Title 화면의 시작 버튼
{
    InitStage();
    state = GameState.Playing;
    Time.timeScale = 1f;
}

// Update(): if (!isDead) 조건을 if (state == GameState.Playing) 으로 교체
// GameOver(): state = GameState.GameOver; 추가
// OnGUI(): switch (state)로 화면별 UI를 나눠 그림
```
- uGUI를 쓴다면 `TitlePanel`, `HudPanel`, `ResultPanel` 세 패널을 Canvas 아래 만들고, 상태가 바뀔 때 `SetActive(true/false)`로 전환한다. 버튼은 인스펙터의 OnClick에 `CsManager.StartGame`을 연결한다(public으로 선언).

**확인할 점**
- `Time.timeScale = 0`이면 `Update()`는 계속 실행되지만 `Time.deltaTime`이 0이 되어 모든 이동이 멈춘다. 반면 CsSky는 `Time.time`을 쓰므로 함께 멈춘다. 타이틀에서 구름이 흐르게 하려면 `Time.unscaledTime`을 쓴다.
- 재시작 버튼이 `SceneManager.LoadScene`을 호출하면 상태가 Title로 돌아간다. 바로 게임이 시작되게 하려면 `static bool skipTitle = true`를 두고 `Start()`에서 확인한다.

#### J-4. 피드백 연출
*제안: 유상현(구현)*

**구현 방향**
- 작은 연출이 게임 필을 크게 바꾼다. 네 가지를 공통 기능으로 만들어 다른 기능들이 불러 쓰게 한다.
  - **팝업 문구:** "+5", "NICE! x10", "MISS", "LEVEL UP" 등이 발생 위치에서 떠오르며 사라진다.
  - **화면 플래시:** 폭탄 피격 시 화면 전체가 빨갛게 번쩍였다 사라진다.
  - **화면 흔들림:** 큰 폭발 시 카메라를 0.2초간 흔든다.
  - **대시 잔상:** F-2에서 구현한다.

**구현 방법**
```csharp
// CsManager — 팝업 문구
class Popup { public string text; public Vector3 pos; public float life; }
List<Popup> popups = new List<Popup>();

/// worldPos가 Vector3.zero이면 화면 중앙에 표시
public void ShowPopup(string text, Vector3 worldPos)
{
    popups.Add(new Popup { text = text, pos = worldPos, life = 1f });
}

// Update()
for (int i = popups.Count - 1; i >= 0; i--) {
    popups[i].life -= Time.deltaTime;
    if (popups[i].life <= 0) popups.RemoveAt(i);
}

// OnGUI()
foreach (Popup p in popups) {
    Vector2 sp;
    if (p.pos == Vector3.zero) sp = new Vector2(Screen.width / 2, Screen.height / 2);
    else {
        Vector3 s = Camera.main.WorldToScreenPoint(p.pos);
        sp = new Vector2(s.x, Screen.height - s.y);          // GUI 좌표는 y가 위에서 아래
    }
    sp.y -= (1 - p.life) * 60;                               // 1초 동안 60픽셀 떠오름
    GUI.color = new Color(1, 1, 1, p.life);                  // 점점 투명
    GUI.Label(new Rect(sp.x - 100, sp.y - 20, 200, 40), "<size='30'><b>" + p.text + "</b></size>");
    GUI.color = Color.white;
}
```
```csharp
// CsManager — 화면 플래시와 흔들림
Texture2D white;                        // Start()에서 white = Texture2D.whiteTexture;
float flash = 0;

public void Flash() { flash = 0.6f; }

public void Shake(float time = 0.2f, float power = 0.3f) { StartCoroutine(ShakeRoutine(time, power)); }

IEnumerator ShakeRoutine(float time, float power)
{
    Transform cam = Camera.main.transform;
    Vector3 origin = cam.position;
    while (time > 0) {
        cam.position = origin + (Vector3)Random.insideUnitCircle * power;
        time -= Time.deltaTime;
        yield return null;
    }
    cam.position = origin;
}

// Update(): flash = Mathf.Max(0, flash - Time.deltaTime * 2);
// OnGUI() 맨 끝:
if (flash > 0) {
    GUI.color = new Color(1, 0, 0, flash);
    GUI.DrawTexture(new Rect(0, 0, Screen.width, Screen.height), white);
    GUI.color = Color.white;
}
```
- CsBomb의 큰 폭발 처리에 `CsManager.inst.Flash(); CsManager.inst.Shake();`를 추가한다.
- CsEgg SAFE 처리에 `CsManager.inst.ShowPopup("+" + point, transform.position);`를 추가한다.

**확인할 점**
- 흔들림 중에 또 흔들림이 시작되면 `origin`이 이미 흔들린 위치로 저장된다. 원래 카메라 위치를 `Start()`에서 한 번 저장해 두고 그 값으로 되돌린다.
- 팝업이 너무 많으면 화면이 산만해진다. 일반 계란 "+1"은 생략하고 콤보 10단위, 황금 계란, 레벨업만 띄우는 식으로 선별한다.

### 2-2. 같은 값을 바꾸는 기능 (충돌 주의)

| 공유하는 값 | 바꾸는 기능 | 해결법 |
|---|---|---|
| 바구니 `localScale` | A-4 피버, C-2 확대 | 효과별 배율 변수를 곱해 매 프레임 계산 |
| `CsBucket.speedMul` | A-4 피버, C-3 운동화 | 효과별 배율 분리 (E-2는 `debuffMul`로 이미 분리) |

| `levelFactor` | D-1, D-2, D-3 | 셋 중 하나만 쓰거나, 스테이지 기본값 × 시간 가속으로 곱함 |

### 2-3. 권장 구현 순서

1. **기반 공사:** 0-1 ~ 0-3, 0-6. 게임 규칙은 그대로이면서 구조만 바뀐다. 이 단계 후 기존과 똑같이 동작하는지 먼저 확인한다.
2. **점수·기록:** A-1 콤보 → A-2 황금 계란 → B-1 최고 점수 → J-4 팝업
3. **아이템:** 0-4, 0-5 → C-1 감속 → C-2 확대 → C-5 하트 → C-4 점수 2배
4. **조작:** F-1 키보드 → F-2 대시 → (선택) F-3 관성
5. **진행 구조:** E-1 하트 표시 → D-2 또는 D-3 → D-4 모드 전환
6. **화면:** J-3 타이틀·결과 → B-3 순위표
7. **확장 (택1, 팀 과제):** G-1 헛간 · H-1/H-2 도감 · H-3 상점 · H-4 강화 · I-1/I-2/I-3 전투 · J-2 날씨

각 단계가 끝날 때마다 **빌드해서 처음부터 끝까지 한 판 플레이**하고, 재시작 후에도 값이 제대로 초기화되는지 확인한다. static 변수 초기화 누락이 가장 흔한 버그다.
